## 재사용과 증거

앱 시퀀스 **F103RB RTU - RAM·카운터·LED 읽기 확인**을 새로 등록했다.
RTU 진입 + RAM 읽기 + 카운터/LED 상태 읽기 + 코일 읽기의 4단계, repeatCount 1이다.
등록 후 정의를 다시 읽어 정확히 대조했으며 추가 실행은 하지 않았다. 기존 GUI RX Check 시퀀스는 보존했다.
이 조회용 시퀀스는 쓰기·카운터 증가 관계·CRC의 자동 판정까지 대신하지 않는다.

- [전체 판정·25개 RTU 패킷·29개 캡처](../../artifacts/modbus-plugin-live-20261113-235119/report.json).
- [복사한 원본 RX의 SHA256 목록](../../artifacts/modbus-plugin-live-20261113-235119/sha256.txt).
- [재사용 시퀀스 정의](../../artifacts/modbus-plugin-live-20261113-235119/read-check.sequence.json).
- report.json SHA256: `93f7daeac3f885d7f6e7560cfb3d0e79f640ec9aebce4857f7b2950781282857`.

원본 `.rx.bin`, 제어 API JSON 및 검사 스크립트는 같은 로컬 증거 폴더에 있으며 Git에는 포함하지 않는다.
실행 중 portable 패키지의 CLI 경로가 없어져 BUILD 조회 프로세스 시작 전 한 번 실패했다.
해당 호출은 송신되지 않았고, 기존 빌드 CLI의 capabilities와 같은 연결 세대를 다시 확인한 뒤 계속했다.
전송된 요청이나 결과가 불확실한 요청을 자동 재시도하지 않았다.

마지막 상태는 **COM3 연결 유지, idle, RAM·LED 원복, 조용한 RTU**, 시리얼 오류 0이다.
카운터는 시험에 따른 증가를 보존했다. LED는 코일과 두 펌웨어 상태 매핑으로 확인했으며 실제 빛의 시각 확인은 하지 않았다.
이 시험은 제어 API를 통한 실제 RTU 통신이며, 화면의 읽기/쓰기 버튼과 레지스터 모니터 자동 폴링 실행기를
직접 실행한 시험이나 장시간 안정성·RS-485 전기 특성 검증은 아니다.
