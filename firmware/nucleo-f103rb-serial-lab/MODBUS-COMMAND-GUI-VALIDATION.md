# 2026-11-14 최신 GUI의 명령·상태 표시 실물 확인

`d10ca71`의 표시 수정과 `f70d053`을 포함한 분리 작업 트리의 최신 Debug
`SerialMonitor.UpdatePreview.exe`를 빌드해 Computer Use로 실제 버튼을 실행했다.
Release·Debug 빌드는 경고·오류 0, 통합 관련 검사는 Core 164 + WinUI 478 통과(환경 조건부 1개 제외)다.
현재 공유 작업 폴더의 별도 미커밋 UI 개편은 이 빌드에 포함하지 않았다.

COM3 / ST-LINK VCP, 115200 / 8N1 / handshake None / HEX / byte timeout 40ms.
실제 ID/BUILD는 NUCLEO-F103RB SERIAL-LAB/1, FW 1.7.1 / 22F524185C55784C로 다시 대조했다.
시험용 명령과 두 감시 영역만 임시 프로필에 넣었으며, 원본 프로필을 별도 보관했다.

GUI에서 명령을 실행한 위치와 원시 패킷을 대조했다. 명령 완료·조건 미충족·정지의 화면 상태는
Computer Use로 관찰한 결과이며, 화면 문자열을 제어 API로 읽어 단정한 결과가 아니다.
지연 ACK 중 정지·CRC·DROP·늦은 ACK·예외 응답은 [명령 실행기 실물 시험](MODBUS-COMMAND-VALIDATION.md)에서 별도로 확인했다.

## 독립 검산과 원복

- 앱 파일 로그의 **TX 448개 / RX 448개**를 모두 분리해 CRC·길이·주소·값을 검산했다.
- GUI 쓰기는 6회: ON/OFF, OFF(조건 실패), OFF(정지), ON/OFF(폴링 중). 펌웨어 카운터는
  **32 → 34 → 35 → 36 → 38**로 증가해 정확히 일치했다.
- 실제 FC06 센티널 쓰기는 없었다. RAM 4워드와 코일 16개는 시험 전후 모두 0으로 같았다.
  폴링 중 명령의 네 교환 사이에 다른 요청이 끼지 않았고 이후 두 영역의 읽기가 모두 이어졌다.
- 제어 API 조회 16개 캡처의 전체 페이지·원본 파일 길이·누락/직렬 오류/수신 간격 유실 0을 확인하고 원본을 별도 복사했다.
- 마지막 GUI 시험이 끝난 뒤 사용자가 Esc로 Computer Use를 중지했다. 후속 상태 조회는
  `instance_not_found`였으며 시험 프로세스가 종료된 것을 확인했다. 실패한 상태 조회를 송신 재시도로 바꾸지 않았다.
- 앱 종료로 저장된 시험 입력 이력을 별도 보관하고 기존 프로필을 정확히 복원했다.

  추가 장치 쓰기·리셋·Flash 기록은 하지 않았다.

## 실물 흐름에서 확인한 UX 정리 우선순위

표시 잔류 오류는 수정·확인했으며, 화면 배치 개편은 아래 정리안으로 남긴다.

1. **표 공간부터 확보:** 1186×793 기본 창의 작은 하단 패널에서는 실행 줄·설정 줄·그룹 줄·두 줄 요약이 쌓여
   값 행보다 헤더가 대부분을 차지했다. 실행 도구 줄과 대상 도구 줄 두 줄로 묶고 그룹 상태는 짧은 집계로 표시한다.
2. **명령 실행과 정지를 함께 배치:** 현재는 팝업 안에서 실행하고 바깥 공통 줄에서 정지한다.
   명령명·단계·고정 대상·실행/정지·최근 결과를 한 위치에 두고 편집 후 같은 위치로 돌아오게 한다.
3. **설명·저장 단계 축소:** 오류 원문이 상단·팝업 요약·단계·오류 영역에 반복돼 대상이 잘리는 것을 확인했다.
   짧은 결과 요약 하나와 펼치는 상세로 나누고, HEX·고급 설정은 필요할 때 펼친다.
   단계/명령 반영·모니터 적용·프로필 저장의 차이를 명확히 하고 불필요한 중간 저장 조작을 줄인다.

전체 시나리오별 제안은 [UX 검토 문서](../../docs/modbus-workflow-ux-review.md)에 있다.
이번 확인은 짧은 실물 UART 및 GUI 시험이며 장기 부하·RS-485 전기 특성·LED 빛의 육안 검증은 포함하지 않는다.
