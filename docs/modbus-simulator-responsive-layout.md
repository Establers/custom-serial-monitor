# 장치 시뮬레이터의 좁은 패널 배치

제품 선택과 응답 버튼, 장치 요약과 값 조작 버튼이 한 행의 폭을 나눠 쓰면서
좁은 도킹 패널에서 제품명이 과도하게 잘리고 요약문이 한두 글자씩 줄바꿈되던 문제를 수정했다.

- 패널 폭 600 DIP 미만에서는 응답 시작·중지를 제품 선택 아래로 옮긴다.
- 장치 ID·항목 수·응답 지연은 독립된 한 줄로 표시한다. 긴 요약은 줄임표와 전체 내용 툴팁을 제공한다.
- 값 변경·초기값 복원과 설명·출처·지원 기능은 340 DIP 미만에서 두 행으로 나눈다.
- 버튼과 드롭다운의 기존 공통 스타일·높이·5 DIP 좌측 여백을 유지한다.
- 표는 항목 → 값 → 주소 → 마지막 변경 순서다. 최소 폭 520 DIP를 유지하고
  좁으면 헤더와 행을 함께 가로 스크롤한다. 항목·값은 처음부터 보이며, 세로 스크롤과 선택은 ListView가 담당한다.

검증은 실제 WinUI 자식 프로세스에서 수행하며 COM 연결·송신·프로필 저장은 하지 않는다.

```powershell
./scripts/test_modbus_layout_native.ps1 -AppPath <빌드한-앱.exe> -CaseFilter sensor-narrow
```

1280×900·800×600 창에서 패널 폭 320·339·340·350·560·599·600·740 DIP,
높이 240·320 DIP와 다시 좁히기를 검사한다. 요약문 높이, 제품 선택 폭, 버튼 경계,
항목·값 표시, 헤더/행 정렬, 양방향 스크롤 끝 도달, 행 선택 바인딩을 확인한다.
기존 명령·이벤트·데이터 바인딩은 유지하며 제품 요약 툴팁만 추가한다.

최종 Release 빌드 경고·오류 0, 네이티브 레이아웃 36건 통과.
350×240 DIP 패널에서 제품 선택 폭 233 DIP, 요약 높이 약 16 DIP, 값 목록 높이 94 DIP를 확인했다.
전체 결과: `artifacts/sensor-narrow-layout/fc5b22e12fe9453aa1cf81a2db40b1aa/result.json`.

검증한 앱은 다른 세션의 미커밋 변경을 제외한 `82683e8` 기준 소스와 이번 변경으로 빌드했다.
실행 중인 앱과 포터블 배포본은 교체하지 않았다. 다른 DPI와 접근성 글꼴 배율은 별도 확인 대상이다.
