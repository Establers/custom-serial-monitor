# 읽기 설정 팝업 위치 유지

읽기 설정에서 **값 표시·바이트 순서**나 **사용 도움말**을 펼치면 내용 높이가 증가했다.
WinUI Flyout이 화면 안에 들어갈 위치를 다시 선택하면서 팝업이 옆으로 이동할 수 있었다.

팝업을 열 때 기존 `FitEditor`가 계산한 최대 높이를 스크롤 영역의 높이로 확보한다.
펼친 내용은 내부 스크롤로 확인하며, 접기·펼치기로 팝업 위치와 크기를 바꾸지 않는다.
창 크기에 따른 기존 높이 제한과 공통 Flyout 스타일은 유지한다.

## 검증 (2026-11-15)

- 다른 작업의 미커밋 변경이 없는 별도 작업 폴더에서 검증했다.
- 수정 전 800×600 창의 아래쪽 읽기 설정에서 첫 펼침 메뉴를 열면 왼쪽 75 DIP,
  위쪽 6 DIP 이동했다. 1280×900에서는 위쪽 54 DIP 이동했다.
- 수정 후 1280×900·800×600, 위쪽 왼편·아래쪽 오른편의 4개 배치에서
  각각 두 메뉴의 개별 펼치기·접기와 동시 펼치기, 총 20개 상태의 좌표 변화가 0 DIP였다.
- 두 메뉴를 펼친 뒤 스크롤 끝 도달을 확인했다. 작은 창에서도 저장 버튼까지 접근할 수 있다.
- Release 솔루션 빌드 경고·오류 0. Modbus/Protocol 검사 896건 통과,
  가상 COM 환경이 필요한 3건은 건너뛰었다.
- 실제 WinUI 자식 프로세스에서 검사했으며 사용자 프로필은 유지됐다.
  COM 연결·송신, 마우스 조작 및 다른 DPI 배율 검사는 하지 않았다.
- 결과: `artifacts/settings-position-after/4ee02687d4e94a92abb148b5e4f0cf1d/result.json`.

검증한 빌드의 실행 파일을 지정해 재검사한다.

```powershell
.\scripts\test_modbus_layout_native.ps1 -AppPath <빌드한-SerialMonitor.WinUI.exe> -CaseFilter settings-position
```
