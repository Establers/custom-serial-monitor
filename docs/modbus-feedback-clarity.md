# Modbus 텍스트와 피드백 정리

2026-11-14 사용자 화면 피드백에 따라 명령·직접 쓰기·그룹 선택과 패킷 값 해석을 정리했다.

- 정상 그룹 선택에는 이름과 대상만 표시한다. 오류·비활성 상태는 계속 표시한다.
- 직접 쓰기와 명령의 긴 사용 안내는 제목 옆 **?**로 옮겼다.
- 명령 대상·값·확인 방식은 한 번 표시하고 HEX 상세는 단계 번호와 바이트만 표시한다.
- 최근 결과는 실행 당시 명령명·짧은 상태·단계 진행으로 요약하고, 단계별 쓰기/확인 대상·원시 값은 접힌 상세에 둔다.
  응답만 받은 경우의 동작 완료 미확인, 정지 시 이미 보낸 쓰기의 반영 가능성, 실패 이유는 구분한다.
- 직접 쓰기는 전용 상태·오류를 사용한다. 이전 명령의 성공 문구를 표시하지 않으며 대상·입력 변경 시 오래된 쓰기 결과를 지운다.
- 팝업 폭과 오른쪽 여백을 줄이고 결과는 줄바꿈해 가로 스크롤을 줄인다.

## FC06 패킷의 역할과 값

[Modbus V1.1b3 6.6절](https://www.modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf)의
FC06 정상 응답은 요청의 주소·값을 되돌려준다. 따라서 RX 바이트만으로 역할을 확정하지 않는다.
이것과 주소·값을 읽을 수 있는지는 별개다.

`01 06 10 10 00 0F CC CB`는 CRC가 정상인 8바이트 패킷이며 주소 4112(0x1010), 값 15다.
값 해석기는 UInt16/Int16·바이트 교환·배율을 적용하고, 32비트 형식에는 짝 레지스터가 없음을 표시한다.
원본 프레임의 역할은 그대로 둔다. FC05 코일, 마스크 쓰기·진단 패킷을 레지스터 읽기 값으로 해석하지 않는다.
CRC 오류·불완전·잘못된 길이·범위 밖 Unit은 계속 거부한다.

## 자동 확인

Release x64 빌드 경고·오류 0개, 관련 WinUI Modbus 검사 520개가 통과했다.
사용자 FC06 원문, 역할 3종과 broadcast, CRC·길이·Unit 경계, 값 해석·배율·32비트 경계,
직접 쓰기 결과 소유권·초기화·실패·정지, 최근 실행 대상 보존을 포함한다.
통신 서비스·프레이머·송신 재시도 정책은 변경하지 않았다.

다른 UI 세션의 버튼·간격·대상 요약과 숫자 칸 폭 변경을 `bd346bf`로 정상 통합했다.
통합 Release x64 빌드는 경고·오류 0개, 전체 WinUI 검사 2,303개 통과·환경 조건부 17개 제외다.
상태/오류의 전용 바인딩, HEX 중복 제거, 접힌 결과 상세, 한/영 리소스 930개 일치와 문서 링크도 확인했다.
사용자의 Computer Use 중단 요청에 따라 이번 추가 GUI 렌더링·조작 검증은 실행하지 않았다.
픽셀 단위 정렬·가로 스크롤 여부는 실제 실행 확인을 남긴다. 실물 UART 송신도 하지 않았다.
