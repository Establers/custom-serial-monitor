# Modbus RTU 레지스터 모니터

기존 **Protocol → Modbus RTU**에서 **레지스터 모니터** 보기를 선택한다.
새 상위 탭을 추가하지 않으며 **패킷 분석**으로 돌아가 원본 요청·응답을 확인할 수 있다.
보기 이동은 폴링을 시작하거나 멈추지 않는다. 실행 중에는 두 보기 모두에 정지 조작을 제공한다.

## 사용 흐름

1. 기존 연결 설정에서 장치의 COM·속도·패리티·정지 비트를 지정하고 연결한다. RTU는 8 data bits를 사용한다.
2. 레지스터 모니터의 **설정**을 열고 장치 ID, 읽기 기능, 시작 주소, 수량을 확인한다.
   주소는 실제 프로토콜의 **0 기준 오프셋**이다. 예를 들어 Holding Register 40001은 `0`이다.
   ID·주소·수량은 10진수 또는 `0x` HEX를 입력한다.
3. **한 번 읽기**로 대상과 값 해석을 확인한다. **폴링 시작**은 같은 영역을 반복해서 읽는다.
4. 표에서 주소·원본 HEX·해석 값·상태·마지막 응답 시각을 확인한다.
5. FC01/FC03 영역은 행을 선택하고 **직접 쓰기…**를 연다. 쓰기 주소와 원시 값을 확인한 뒤 **쓰기 및 확인**을 누른다.
6. **설정 저장**은 현재 앱 프로필에 설정을 저장한다. 불러오기는 기존 프로필 불러오기를 사용한다.

앱 시작·프로필 불러오기·포트 재연결은 자동 송신을 시작하지 않는다.
일반 프로필 저장과 종료 저장에서 Modbus 입력을 편집 중이어도 다른 앱 설정 저장은 계속된다.
잘못된 Modbus 초안은 마지막 저장 가능한 설정을 보존하고, 전용 설정 저장·읽기·쓰기는 잘못된 입력을 거부한다.
외부 프로필의 잘못된 장치 주소는 다른 유효 주소로 자동 변경하지 않으며 수정 전 송신할 수 없다.

## 읽기와 표시

- 한 연결에서 **장치 하나의 연속 영역 한 개**를 감시한다. 여러 장치/영역 편집기는 이번 범위에 포함하지 않는다.
- FC01/02는 최대 2,000비트, FC03/04는 최대 125레지스터다. 시작 주소와 끝 주소는 0–65535다.
- 주기는 응답 처리 후 다음 읽기까지의 대기 시간이며 100–60,000ms다. 밀린 요청을 연속 송신하지 않는다.
- 응답 제한 시간은 송신 시작부터 100–10,000ms다. Windows/USB 환경에서 정확한 실시간 주기를 보장하지 않는다.
- 레지스터 형식은 UInt16·Int16·UInt32·Int32·Float32, 배율 및 바이트/워드 교환을 지원한다.
  표시 설정은 송신되는 원시 값을 바꾸지 않는다. 32비트 값은 레지스터 두 개를 사용한다.
- 갱신 시 기존 행 객체를 유지하여 선택을 보존한다. UI는 주기적으로 최신 스냅샷을 반영한다.
- 마지막 정상 값을 보존할 수 있으나 정지·오류·연결 변경 시 현재 통신 값으로 표시하지 않는다.
  한 번 읽기 성공은 마지막 정상 응답으로 표시하며 연결이 바뀌면 오래된 값으로 바뀐다.

## 직접 쓰기

- FC01에서 단일 코일 FC05 또는 여러 코일 FC0F, FC03에서 단일 레지스터 FC06 또는 여러 레지스터 FC10을 사용한다.
- 쓰기 값은 **배율을 적용하지 않은 원시 UInt16**(0–65535 또는 `0x` HEX)이다. 코일은 `0`/`1`이다.
  공백·쉼표·세미콜론·줄바꿈으로 여러 값을 입력하면 연속 주소에 쓴다.
- 전체 쓰기 범위는 감시 영역 안이어야 한다. 여러 쓰기는 코일 1,968개/레지스터 123개까지다.
- 쓰기 응답을 검증한 뒤 감시 영역을 다시 읽어 실제 원시 값과 비교한다.
  응답 확인과 재조회 불일치를 구별한다. 일치하지 않는 장치 동작은 자동으로 다시 쓰지 않는다.
- 폴링 중 쓰기는 최대 한 건만 대기하며 현재 요청이 끝난 뒤 실행한다. 중복 클릭/추가 대기는 거부한다.
- ID 0 브로드캐스트는 확인 응답과 재조회가 없으므로 이 화면에서 지원하지 않는다.

## 송신 소유권과 오류 처리

폴링·한 번 읽기·직접 쓰기는 물리 연결 세대에 묶인 배타적 소유권을 사용한다.
소유 중에는 GUI/AI 시퀀스·수동 송신·터미널 직접 입력·브리지·통신 설정/제어선 변경을 거부한다.
이미 시작한 시퀀스·명령·설정 변경·브리지가 있으면 Modbus를 시작할 수 없다.
터미널 직접 입력을 끈 뒤 시작한다. 실제 전송 계층도 같은 규칙을 검사한다.

**정지**는 다음 요청과 대기 중 쓰기를 취소하되 진행 중인 송신/응답은 제한 시간까지 마무리한다.
해당 작업이 끝나기 전에 다른 송신자에게 연결을 넘기지 않는다. 즉시 중단해야 하면 기존 연결 해제를 사용한다.
정지 직전에 쓰기가 이미 시작되었다면 장치에 반영되었을 수 있으며, 재조회하지 못한 결과는 미확인으로 표시한다.

RTU 읽기 응답에는 요청 주소나 트랜잭션 ID가 없다. 타임아웃 후 다음 요청을 계속하면
늦은 응답을 다른 요청의 값으로 오인할 수 있다. 따라서 타임아웃·CRC 오류·형식 불일치·수신 유실 등
완료를 확정할 수 없는 경우에는 원래 연결을 종료한 뒤 소유권을 해제한다.
자동 재연결/폴링 재시작은 하지 않으며 사용자가 연결과 대상을 확인하고 다시 실행한다.
정상 형식의 Modbus 예외 응답이나 쓰기 재조회 불일치는 오류를 표시하고 실행을 끝내지만 연결 자체를 종료하지 않는다.

RX 관측은 기존 수신/파일 로그 파이프라인과 독립된 bounded channel(64청크/64KiB)로 전달한다.
초과는 성공으로 처리하지 않는다. 다른 연결 세대/요청 전 시각의 데이터를 새 요청에 사용하지 않는다.
기존 Protocol의 패킷 이력과 파일 로그는 기존 보관 정책을 따른다.

## 검증 범위

자동 검사는 프로토콜 값·CRC·잘못된 응답·연결 세대·소유권 경합·취소·타임아웃·큐 한도·쓰기 재조회·프로필 및 XAML/뷰모델 동작을 대상으로 한다.
2026-11-13 최종 검증에서 최신 메모리 개선 커밋과 함께 Release 솔루션 빌드(경고·오류 0)를 확인했다.
Core 전체 668개와 실제 작업 폴더의 WinUI 전체 1,921개가 통과했으며, 장치 환경이 필요한 17개는 제외했다.
전체 검사는 `-m:1`, `xUnit.ParallelizeTestCollections=false`, `RunConfiguration.TestSessionTimeout=600000`으로 실행했다.
사용자 요청에 따라 Computer Use와 GUI 수동 조작은 수행하지 않는다.
MOCK의 문자 에코는 실제 Modbus 장치를 모사하지 않으므로 실제 장치 검증으로 간주하지 않는다.
실제 UART 장치, USB 어댑터의 로컬 에코, 장시간 선로 부하와 장치별 쓰기 반영 지연은 별도 실물 검증이 필요하다.
일부 코일 읽기에서는 요청 바이트 자체가 정상 응답 형태와 같을 수 있다. 요청과 완전히 같은 읽기 응답은
로컬 에코와 구별할 수 없어 미확인으로 거부한다. 단일 쓰기의 동일 에코는 재조회를 통과해야 검증 완료가 된다.
