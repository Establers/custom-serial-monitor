# Modbus RTU 레지스터 모니터

기존 **Protocol** 탭의 선택 메뉴에서 **Modbus RTU · 값 읽기/쓰기**를 선택한다.
이 화면이 레지스터 모니터다. 장치에 읽기 요청을 보내 표를 갱신하고, 폴링하거나 값을 쓸 수 있다.
**Modbus RTU · 패킷 분석**은 이미 오간 원본 요청·응답을 해석하는 화면이다.
프로토콜과 보기를 같은 메뉴에서 선택하므로 별도 전환 줄이나 상위 탭을 추가하지 않는다.
한 번 읽기·폴링 시작·정지는 상단에, 대상 설정·직접 쓰기·명령·?는 표 위에 있다. 항목 정의·감시 그룹·프로필 저장은 대상 설정 안에서 연다.
그룹 설정이 없는 기본 단일 영역에서는 그룹 선택 줄이 표시되지 않는다. 빈 표에서도 대상 설정과 한 번 읽기를 바로 열 수 있다.
메뉴 선택만으로 읽기·쓰기·폴링을 시작하거나 멈추지 않는다. 실행 중에는 Modbus의 두 보기 사이만 이동할 수 있고,
미사용/BACnet 전환은 정지한 뒤 가능하다. 정지 버튼은 두 보기에서 같은 상단 위치에 표시한다.
좁은 창에서는 패킷 만들기·목록 비우기·통계 초기화가 더 보기(⋯)로 이동한다. 정지는 메뉴 밖에 유지한다.

읽기/쓰기 화면의 기존 버튼 줄 끝에 있는 **? (사용 안내)**에서 기능의 목적, 패킷 분석과의 차이,
처음 읽는 순서, 감시 그룹, 표시 형식·배율, 직접 쓰기와 시퀀스 사용 시 주의할 점을 확인한다.
안내는 불투명한 팝업으로 열리고 작은 창에서 스크롤할 수 있으며, 안내를 열어도 송신이나 설정 변경을 하지 않는다.

## 사용 흐름

1. 기존 연결 설정에서 장치의 COM·속도·패리티·정지 비트를 지정하고 연결한다. RTU는 8 data bits를 사용한다.
2. 레지스터 모니터의 **대상 설정**을 열고 장치 ID, 읽기 기능, 시작 주소, 수량을 확인한다.
   주소는 실제 프로토콜의 **0 기준 오프셋**이다. 예를 들어 Holding Register 40001은 `0`이다.
   ID·주소·수량은 10진수 또는 `0x` HEX를 입력한다.
3. **한 번 읽기**로 대상과 값 해석을 확인한다. **폴링 시작**은 같은 영역을 반복해서 읽는다.
4. 표에서 주소·원본 HEX·해석 값·상태·마지막 응답 시각을 확인한다.
5. FC01/FC03 영역은 행을 선택하고 **직접 쓰기…**를 연다. 쓰기 주소와 원시 값을 확인한 뒤 **쓰기 및 확인**을 누른다.
6. **프로필 저장**은 현재 앱 프로필에 설정을 저장한다. 불러오기는 기존 프로필 불러오기를 사용한다.

앱 시작·프로필 불러오기·포트 재연결은 자동 송신을 시작하지 않는다.
일반 프로필 저장과 종료 저장에서 Modbus 입력을 편집 중이어도 다른 앱 설정 저장은 계속된다.
잘못된 Modbus 초안은 마지막 저장 가능한 설정을 보존하고, 전용 설정 저장·읽기·쓰기는 잘못된 입력을 거부한다.
외부 프로필의 잘못된 장치 주소는 다른 유효 주소로 자동 변경하지 않으며 수정 전 송신할 수 없다.
알 수 없는 표시 형식은 Modbus 설정만 미확인 상태로 보존한다. 기존 연결·명령 등 다른 프로필 설정은 유지하며,
표시 형식을 고치기 전에는 송신하지 않는다. 감시 대상을 편집하면 이전 대상의 검증 결과와 통계 표시를 해제한다.
연결 교체 등으로 읽기·쓰기 시작이 거절되면 이전 응답을 새 주소의 값으로 표시하지 않는다.

## 읽기와 표시

- 기본 단일 영역 설정과 **감시 그룹…**을 통한 여러 장치·영역 설정을 지원한다. 같은 COM 연결의 모든 그룹은 같은 속도·패리티·정지 비트를 사용한다.
- FC01/02는 최대 2,000비트, FC03/04는 최대 125레지스터다. 시작 주소와 끝 주소는 0–65535다.
- 주기는 응답 처리 후 다음 읽기까지의 대기 시간이며 100–60,000ms다. 밀린 요청을 연속 송신하지 않는다.
- 응답 제한 시간은 송신 시작부터 100–10,000ms다. Windows/USB 환경에서 정확한 실시간 주기를 보장하지 않는다.
- 레지스터 형식은 UInt16·Int16·UInt32·Int32·Float32, 배율 및 바이트/워드 교환을 지원한다.
  표시 설정은 송신되는 원시 값을 바꾸지 않는다. 32비트 값은 레지스터 두 개를 사용한다.
- 갱신 시 기존 행 객체를 유지하여 선택을 보존한다. UI는 주기적으로 최신 스냅샷을 반영한다.
- 마지막 정상 값을 보존할 수 있으나 정지·오류·연결 변경 시 현재 통신 값으로 표시하지 않는다.
  한 번 읽기 성공은 마지막 정상 응답으로 표시하며 연결이 바뀌면 오래된 값으로 바뀐다.

## 여러 장치·영역 폴링

**대상 설정 → 감시 그룹…**에서 그룹을 추가·복제·삭제한다. 그룹마다 이름, 활성 여부, 장치 ID, 읽기 기능,
시작 주소, 수량, 주기, 응답 제한 시간 및 기본 값 형식을 설정한다. **항목 정의…**는 선택한 그룹의
이름·자료형·배율·단위·접근 권한·값 이름을 편집한다. 그룹 편집창의 적용은 송신이나 프로필 저장을 시작하지 않는다.

- 같은 장치의 떨어진 주소 영역 또는 서로 다른 장치 ID를 각각 그룹으로 등록한다. 서로 겹치는 읽기 영역도
  별도 그룹으로 둘 수 있으며, 내부 그룹 ID로 응답·통계·쓰기 대상을 구별한다. 복제는 새 그룹 ID를 만든다.
- 최대 32그룹, 전체 읽기 수량 합계 8,192비트/레지스터 셀이다. 그룹별 수량과 주기 범위는 기존과 같다.
- **활성 그룹 폴링 시작**은 활성 그룹 전체를 하나의 실행기로 순차 처리한다. 한 시점에 요청 하나만 진행하며,
  다음 요청 시각은 해당 그룹의 응답 처리 후 주기를 더해 정한다. 버스 처리량보다 짧은 주기를 지정해도
  요청을 무제한 쌓거나 밀린 횟수만큼 연속 송신하지 않는다. 실제 갱신 간격은 다른 그룹과 장치 응답 시간의 영향을 받는다.
- 그룹 선택은 상세 표만 바꾼다. 폴링 중에도 다른 그룹을 선택할 수 있으며 나머지 그룹의 읽기는 계속된다.
  항상 보이는 요약은 전체·오류·정상 응답·대기/지난 값·비활성 개수와 오류 그룹 이름을 표시한다.
  선택 목록에서도 상태를 먼저 표시하므로 비선택 그룹의 오류를 찾을 수 있다. 요약의 툴팁에는 각 그룹의 상태·원시 값·성공/오류 횟수가 남는다. 상세 표는 선택한 그룹의 값 형식을 사용한다.
- **한 번 읽기**는 정지 상태에서 선택한 그룹만 조회한다. 비활성 그룹도 명시적으로 한 번 읽을 수 있지만,
  자동 폴링과 쓰기에서는 제외한다. 쓰기를 진행하는 동안 그룹 선택을 잠시 잠가 전송 대상과 화면 대상을 맞춘다.
- 그룹·대상·활성 여부·항목 정의 편집은 전체 정지 후 한다. 폴링 중 쓰기는 실행 시작 때 고정한 그룹 ID와 설정을 사용한다.
  다른 장치의 읽기나 쓰기를 쓰기 응답과 재조회 사이에 끼워 넣지 않는다. 전체 대기/진행 쓰기는 한 건이며 자동 재시도하지 않는다.
- 정상 형식의 Modbus 예외나 쓰기 재조회 불일치는 해당 그룹을 오류 상태로 정지하고 다른 정상 그룹은 계속한다.
  타임아웃·CRC 오류·수신 유실 등 완료가 불명확한 오류는 늦은 응답 오인을 막기 위해 연결을 종료하고 전체 그룹을 정지한다.
- **정지**는 모든 그룹의 다음 요청과 대기 쓰기를 취소한다. 진행 중 요청은 기존 응답 제한 시간까지 마무리하고 소유권을 해제한다.
- **프로필 저장**은 모든 그룹과 선택 상태를 앱 프로필에 저장한다. 시작·재연결·불러오기는 자동 폴링하지 않는다.
  기존 프로필은 단일 영역으로 열리며 그룹 편집 시 현재 설정 한 개로 시작한다. 명시적으로 모든 그룹을 비운 설정은
  빈 상태로 보관하며, 이전 단일 영역을 대신 송신하지 않는다. 알 수 없는 선택 ID도 임의의 다른 쓰기 대상으로 바꾸지 않는다.
- 잘못된 외부 그룹·장치 주소·항목 정의는 보존하여 편집기에서 수정/삭제한다. 중복 그룹 ID나 잘못된 메타데이터가 있으면
  한 번 읽기·쓰기로 우회하지 못한다. 프로필의 다른 앱 설정은 유지한다.

## 직접 쓰기

### 항목별 정의와 해석값 쓰기

**항목 정의…**에서 현재 감시 영역 안의 값을 이름과 형식으로 정의한다. 연결 전에도 편집할 수 있으며,
적용은 데이터를 보내거나 프로필을 저장하지 않는다. 적용 후 기존 **프로필 저장**으로 앱 프로필에 보관한다.

- 항목마다 0 기준 주소, 이름, UInt16/Int16/UInt32/Int32/Float32, 배율, 단위, 바이트/워드 순서,
  읽기 전용/읽기·쓰기를 지정한다. 새 항목의 기본 접근 권한은 읽기 전용이다.
- 서로 다른 자료형을 같은 읽기 영역에서 함께 사용한다. 32비트 항목은 연속 레지스터 두 개를 사용하며,
  항목이 겹치거나 감시 영역을 벗어날 수 없다. 정의하지 않은 주소에는 기존 전체 영역 표시 형식을 적용한다.
- 값 이름은 한 줄에 `0=수동`, `1=자동`처럼 입력한다. 숫자는 배율 적용 전의 해석 값이다.
  표에는 이름과 숫자를 함께 표시한다. Coil 항목은 UInt16, 배율 1, 교환 없음으로 정의한다.
- FC02/FC04 영역의 항목은 읽기 전용이다. 항목 정의는 정지 상태에서 편집하며 실행 중의 대상은 변경하지 않는다.
- **직접 쓰기… → 항목 값**은 정의한 항목의 시작 주소에 숫자 또는 값 이름 하나를 입력한다.
  숫자는 표시 단위의 값이다. 예를 들어 배율 0.1인 Int16 항목에 `25.3`을 입력하면 원시 값 253을 쓴다.
  단위 문자열은 입력값에 붙이지 않는다. `자동` 같은 값 이름은 해당 배율 적용 전 숫자로 변환한다.
- 타입과 배율에 맞춰 원시 레지스터를 계산하고 전송할 원시 HEX와 RTU 패킷 미리보기를 표시한다.
  정수 레지스터로 정확하게 표현할 수 없는 입력, 범위 초과, 배율 0 쓰기를 거부한다.
  Float32는 일반적인 부동소수점 반올림을 적용하며 유한 범위 초과와 0으로의 언더플로를 거부한다.
- **원시 값** 모드는 기존 UInt16/Coil 직접 쓰기다. 이 모드에서도 읽기 전용 항목을 우회할 수 없으며,
  정의한 32비트 항목의 한쪽 레지스터만 쓰는 요청은 거부한다. 활성 폴링에 고정된 정의도 전송 계층에서 검사한다.
- 항목이 없는 기존 프로필은 기존과 동일하게 동작한다. 잘못된 외부 항목 정의는 다른 앱 설정을 폐기하거나
  일반 쓰기 가능한 영역으로 바꾸지 않으며, **항목 정의…**에서 수정/삭제하기 전에는 송신을 거부한다.

이 항목 설정은 단일 영역과 각 폴링 그룹에서 사용한다. 직접 쓰기는 아래의 원시 값 재조회 규칙을 따른다.
쓰기 전용·자기 초기화 명령과 별도 상태 주소 확인은 **명령…**에서 독립적으로 정의한다.

- FC01에서 단일 코일 FC05 또는 여러 코일 FC0F, FC03에서 단일 레지스터 FC06 또는 여러 레지스터 FC10을 사용한다.
- 원시 값 모드의 쓰기 값은 **배율을 적용하지 않은 원시 UInt16**(0–65535 또는 `0x` HEX)이다. 코일은 `0`/`1`이다.
  공백·쉼표·세미콜론·줄바꿈으로 여러 값을 입력하면 연속 주소에 쓴다.
- 전체 쓰기 범위는 감시 영역 안이어야 한다. 여러 쓰기는 코일 1,968개/레지스터 123개까지다.
- 쓰기 응답을 검증한 뒤 감시 영역을 다시 읽어 실제 원시 값과 비교한다.
  응답 확인과 재조회 불일치를 구별한다. 일치하지 않는 장치 동작은 자동으로 다시 쓰지 않는다.
- 폴링 중 쓰기는 최대 한 건만 대기하며 현재 요청이 끝난 뒤 실행한다. 중복 클릭/추가 대기는 거부한다.
- 쓰기 중 다른 행을 선택해도 진행 중인 요청의 주소·값은 바뀌지 않는다. 완료 후 새 선택의 주소·값을 입력란에 함께 반영한다.
  같은 행을 계속 선택하고 있으면 사용자가 직접 입력한 쓰기 초안을 유지한다.
- ID 0 브로드캐스트는 확인 응답과 재조회가 없으므로 이 화면에서 지원하지 않는다.

## 명령과 결과 확인

**명령… → 명령 편집…**에서 이름 있는 명령과 순서가 있는 단계를 정의한다.
기본 입력은 대상·값·확인 방식이며, 자료형·배율·교환·단위·응답 시간·값 이름은 고급 옵션에서 지정한다.
저장된 비기본 해석 설정과 잘못된 자료형은 고급 옵션을 펼쳐 보여주고, 접어도 해석 요약을 표시한다. 단계마다 장치 ID,
쓰기 영역(Coils / Holding registers), 0 기준 주소, 자료형·배율·바이트/워드 순서와 쓸 값을 지정한다.
32비트 값은 두 레지스터를 한 번에 쓴다. 감시 영역 밖의 쓰기 전용 주소도 지정할 수 있으며, 감시 그룹이 없어도 실행할 수 있다.
기존 감시 항목과 같은 장치·영역에서 겹치면 읽기 전용 보호와 32비트 전체 쓰기 규칙을 적용한다.

| 결과 확인 방식 | 실행과 표시 |
| --- | --- |
| 쓴 값 재조회 | 쓰기 응답을 확인하고 같은 장치·주소의 원시 값을 읽어 전체 일치를 확인한다. |
| 별도 상태 주소·비트 | 쓰기 응답 후 같은 장치의 FC01–04 상태 주소 하나를 읽는다. 제한 시간 안에 `(원시 값 & 마스크) == 기대값`이면 통과한다. |
| 응답 확인만 | 쓰기 응답까지만 확인한다. 읽기 요청은 보내지 않으며 **동작 완료는 확인하지 않음**으로 표시한다. |

- 상태 주소는 16비트 원시 레지스터 또는 비트 하나다. 마스크와 기대값은 배율을 적용하지 않은 값이며,
  비트 영역의 마스크는 1, 기대값은 0 또는 1이다. 레지스터 bit 3만 확인하려면 마스크 `0x0008`, 기대값 `0x0008`을 사용한다.
- 예를 들어 실행 직후 0으로 돌아가는 시험 명령은 **응답 확인만** 또는 **별도 상태 주소**를 사용한다.
  실제 위치·운전 상태가 중요한 장치에서는 응답 수신과 상태 조건 충족을 구분한다.
- 단계와 명령 선택 시 대상과 전송 HEX를 미리 확인한다. **선택 명령 실행**을 눌러야 송신하며,
  편집 적용·프로필 저장/로드·재연결은 실행하지 않는다. 저장한 명령은 장치 ID까지 포함한 고정 정의이며,
  감시 표에서 선택한 그룹을 바꿔도 실행 대상은 바뀌지 않는다.
- 한 명령은 등록된 단계 순서대로 실행한다. 앞 단계가 지정한 확인 방식을 통과한 뒤 다음 쓰기를 시작한다.
  응답 확인만인 단계는 ACK 수신 후 진행하므로, 실제 동작 완료가 필요하면 상태 확인을 지정한다.
  실패·조건 미충족·정지 시 뒤 단계는 실행하지 않는다. 단계별 응답 수신 여부와 확인 결과를 따로 표시한다.
- **쓰기 자동 재시도는 없다.** 상태 확인은 설정한 간격으로 읽기만 반복한다.
  정상 응답은 왔지만 상태가 제한 시간 안에 맞지 않으면 해당 명령을 끝내고 원인을 표시한다.
  무응답·CRC 오류 등 완료 불명 오류는 기존 연결 종료 규칙을 적용한다.
- 폴링 중 명령은 현재 요청 다음에 실행하며, 명령의 쓰기와 상태 확인 사이에 다른 폴링·쓰기를 끼워 넣지 않는다.
  대기/실행 중인 직접 쓰기와 명령을 합쳐 한 건만 허용한다. 명령 뒤에는 기한이 된 폴링에 차례를 준다.
  기존 GUI/AI 시퀀스·브리지·수동 TX와 동일한 연결 소유권 보호를 사용한다.
- 명령 팝업 안의 **명령·폴링 정지**와 바깥 공통 **정지**는 같은 작업을 멈춘다. 명령 편집을 적용하면 실행 팝업으로 돌아오며 자동 실행하지 않는다.
- 공통 **정지**는 폴링과 명령을 함께 멈춘다. 진행 중 응답은 제한 시간까지 마무리하며,
  이미 응답을 받은 쓰기는 장치에 적용됐을 수 있다. 확인하지 못한 결과를 성공으로 표시하지 않는다.
- 독립 명령이 끝나면 상단에 최종 결과와 실제 명령 대상을 함께 유지한다. 다음 읽기·쓰기·설정 변경은
  감시 대상의 상태로 돌아간다. 폴링 중 명령이 끝나면 상단은 재개한 폴링 상태·선택 그룹을 표시하며,
  최근 명령의 실제 대상과 결과 요약은 팝업 밖에도 표시하고, 상세 결과는 **명령…**에 보존한다.
  다른 명령을 선택하거나 읽기/폴링을 시작해도 최근 실행 결과를 새 대상의 결과로 바꾸지 않는다. 실행 중 그룹을 바꿔도 명령 대상 표시는 바뀌지 않는다.
- 명령은 최대 32개, 명령당 최대 32단계다. 단계 응답 제한은 100–10000ms, 상태 확인 제한은
  100–60000ms, 확인 간격은 100ms 이상이다. 명령당 설정상 제한 시간의 합계는 최대 300000ms이며,
  RTU 무송신 간격과 정지 시 진행 중 응답 마무리 시간은 추가될 수 있다. 결과 이력은 마지막 명령 한 건만 보관한다.
- **프로필 저장**으로 명령 목록과 선택 상태도 앱 프로필에 저장한다. 잘못된 외부 정의는 송신 가능한 기본값으로
  바꾸지 않고 보존한다. 명령 편집기에서 수정하거나 삭제한 뒤 실행한다.

## 송신 소유권과 오류 처리

폴링·한 번 읽기·직접 쓰기는 물리 연결 세대에 묶인 배타적 소유권을 사용한다.
소유 중에는 GUI/AI 시퀀스·수동 송신·터미널 직접 입력·브리지·통신 설정/제어선 변경을 거부한다.
이미 시작한 시퀀스·명령·설정 변경·브리지가 있으면 Modbus를 시작할 수 없다.
터미널 직접 입력을 끈 뒤 시작한다. 실제 전송 계층도 같은 규칙을 검사한다.
일반 송신·속도 변경·Modbus 시작은 잠금이나 작업자 대기 전에 원래 연결을 고정한다.
대기 중 연결이 교체되면 새 연결에 이전 명령을 보내거나 설정을 적용하지 않는다.

**정지**는 다음 요청과 대기 중 쓰기를 취소하되 진행 중인 송신/응답은 제한 시간까지 마무리한다.
해당 작업이 끝나기 전에 다른 송신자에게 연결을 넘기지 않는다. 즉시 중단해야 하면 기존 연결 해제를 사용한다.
정지 직전에 쓰기가 이미 시작되었다면 장치에 반영되었을 수 있으며, 재조회하지 못한 결과는 미확인으로 표시한다.

RTU 읽기 응답에는 요청 주소나 트랜잭션 ID가 없다. 타임아웃 후 다음 요청을 계속하면
늦은 응답을 다른 요청의 값으로 오인할 수 있다. 따라서 타임아웃·CRC 오류·형식 불일치·수신 유실 등
완료를 확정할 수 없는 경우에는 원래 연결을 종료한 뒤 소유권을 해제한다.
자동 재연결/폴링 재시작은 하지 않으며 사용자가 연결과 대상을 확인하고 다시 실행한다.
정상 형식의 Modbus 예외 응답이나 쓰기 재조회 불일치는 오류를 표시하고 해당 실행/그룹을 끝내지만 연결 자체를 종료하지 않는다.

RX 관측은 기존 수신/파일 로그 파이프라인과 독립된 bounded channel(64청크/64KiB)로 전달한다.
초과는 성공으로 처리하지 않는다. 다른 연결 세대/요청 전 시각의 데이터를 새 요청에 사용하지 않는다.
기존 Protocol의 패킷 이력과 파일 로그는 기존 보관 정책을 따른다.
불완전 응답이 확인 가능한 RTU native idle 경계에서 끝나면 다음 조각과 합치지 않는다.
판정에는 실제 적용된 속도·데이터/패리티/정지 비트와 native idle 시간을 사용한다.
일반 USB 수신 조각의 분할이나 Windows 작업자 지연만으로 프레임 경계를 추정하지 않는다.

## 검증 범위

명령과 결과 확인 확장은 Release 솔루션 빌드(경고·오류 0), Core 723개와 WinUI 2,222개 검사를 통과했다.
실제 장치 환경이 필요한 17개는 제외했다. 명령 검사는 쓰기 전용 ACK, Float32 전체 쓰기·재조회,
별도 FC04 주소의 상태 비트, 여러 ID의 순서, 전체 단계 사전 검사, 폴링 중 실행·상호 배제,
정지·연결 교체·CRC·늦은 상태 응답과 손상 프로필을 포함한다.
최신 Debug 검증 빌드의 GUI에서 응답만 확인 정책, 단계 추가·복제·값 변경·순서 변경,
정의 적용 후 순서에 맞는 쓰기 HEX 미리보기를 확인했다. GUI 시험은 연결하지 않은 상태로 진행했고,
프로필 저장과 실제 장치 송신은 실행하지 않았다. 실제 제품의 명령 동작·장시간 부하 시험은 별도다.

여러 장치·영역 폴링 확장은 Release 솔루션 빌드(경고·오류 0), Core 723개와 WinUI 2,111개 검사를 통과했다.
실제 장치 환경이 필요한 17개는 제외했다. 같은 소스의 최신 Debug 검증 빌드에서 그룹 복제, 장치 ID 변경,
그룹 편집창과 항목 편집창의 전환/복귀, 그룹 적용 및 선택에 따른 대상 전환을 Computer Use로 확인했다.
이 GUI 확인에서는 실제 UART 요청이나 프로필 저장을 실행하지 않았다. 실제 여러 장치 연결 및 장시간 버스 부하 시험은 별도다.

자동 검사는 프로토콜 값·CRC·잘못된 응답·연결 세대·소유권 경합·취소·타임아웃·큐 한도·쓰기 재조회·프로필 및 XAML/뷰모델 동작을 대상으로 한다.
2026-11-13 초기 구현 검증에서 최신 메모리 개선 커밋과 함께 Release 솔루션 빌드(경고·오류 0)를 확인했다.
Core 전체 668개와 실제 작업 폴더의 WinUI 전체 1,921개가 통과했으며, 장치 환경이 필요한 17개는 제외했다.
전체 검사는 `-m:1`, `xUnit.ParallelizeTestCollections=false`, `RunConfiguration.TestSessionTimeout=600000`으로 실행했다.
후속 안정성 검토에서는 연결 교체·확정 프레임 경계·설정 호환성·선택 동기화·시작 거절에 대한 새 회귀 검사 38개를 추가했다.
수정 후 Release 빌드의 경고·오류는 0이며, Core 전체 668개와 메모리 통합 검사를 포함한 WinUI 1,963개가 통과했다(장치 조건부 17개 제외).
초기 구현 당시에는 사용자 요청에 따라 Computer Use와 GUI 수동 조작을 수행하지 않았다.
MOCK의 문자 에코는 실제 Modbus 장치를 모사하지 않으므로 실제 장치 검증으로 간주하지 않는다.
실제 UART 장치, USB 어댑터의 로컬 에코, 장시간 선로 부하와 장치별 쓰기 반영 지연은 별도 실물 검증이 필요하다.
일부 코일 읽기에서는 요청 바이트 자체가 정상 응답 형태와 같을 수 있다. 요청과 완전히 같은 읽기 응답은
로컬 에코와 구별할 수 없어 미확인으로 거부한다. 단일 쓰기의 동일 에코는 재조회를 통과해야 검증 완료가 된다.
