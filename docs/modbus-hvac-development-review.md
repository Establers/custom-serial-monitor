# 에어컨·외부 센서 개발 관점의 Modbus 기능 검토

검토일: 2026-11-15. 소스 기준 `53da41f` 및 이번 드롭다운 여백 수정.
이번 검토는 소스와 제조사 공개 문서 대조다. 에어컨·서드파티 센서 실물을 연결한 호환성 시험은 아니다.
이전 NUCLEO 실기 결과만으로 모든 제품의 호환성을 보증하지 않는다.

## 적합한 사용 범위

현재 장치 감시·제어는 PC가 요청하는 Modbus RTU 클라이언트(마스터) 도구다.
센서의 통신 설정·레지스터 맵을 먼저 확인하거나 에어컨의 서버(슬레이브) 구현을 시험하기에 유용하다.
에어컨이 외부 센서를 읽는 클라이언트 구현 자체를 시험하려면 별도 센서 응답기가 필요하다.

| 개발 작업 | 현재 적합성 | 실제 사용 방법 / 한계 |
| --- | --- | --- |
| 외부 온습도·CO₂ 센서 단독 확인 | 적합 | PC가 센서를 읽어 주소·자료형·배율·통신 설정을 확인 |
| BMS가 읽고 제어할 에어컨 서버 개발 | 적합 | PC가 BMS의 요청을 대신해 읽기·쓰기·상태 조건을 확인 |
| 에어컨의 센서 조회 로직 검증 | 부분적 | 실제 센서 연결 전 단독 점검은 가능. 앱이 센서 역할로 응답하는 기능은 없음 |
| 에어컨↔센서 실제 통신 문제 분석 | 수신 경로가 갖춰지면 유용 | 패킷 분석 사용. 양방향 수집용 RS-485 수신 연결/탭이 필요하며 앱만으로 버스가 보이지는 않음 |
| 여러 센서의 온도 변화·장시간 품질 비교 | 부족 | 여러 읽기 그룹은 있으나 선택 그룹 표 중심. 항목별 시계열·동시 비교 화면·품질 보고가 필요 |

이미 동작 중인 에어컨이 RTU 마스터라면 같은 버스에서 PC 자동 읽기를 동시에 켜지 않는다.
앱 내부의 연결 소유권은 외부 에어컨의 송신을 조정하지 않는다.
단독 검사 때는 PC를 마스터로 사용하고, 통합 검사 때는 수신 전용 관찰 경로를 사용한다.
근거: [Modbus 공식 Serial Line 가이드](https://www.modbus.org/file/secure/modbusoverserial.pdf).

## 실제 센서 문서와의 대조

[Belimo 공기질 센서 공식 레지스터 문서](https://www.belimo.com/mam/general-documents/system_integration/Modbus/belimo_Modbus-Register_AirQualitySensor_2205_en-gb.pdf)의
측정값 표는 온도 주소 0 / signed / 배율 0.1, 상대습도 주소 1 / signed / 배율 0.1,
CO₂ 주소 5 / signed / 배율 1.0을 정의한다. 실제 모델의 지원 항목과 단위 설정을 확인해야 한다.
현재 이름·단위·Int16·배율·FC03 읽기로 이 표현을 구성할 수 있다.
문서의 통신 기본값은 9600 / 8N2이므로 NUCLEO 시험의 115200 / 8N1을 그대로 쓰면 안 된다.
등록 번호와 전송 주소의 차이도 중요하다. 위 문서의 Register No. 1은 전송 주소 0이다.

## 소스에서 확인한 기반

- `ModbusMonitorSettings`: FC01–04 읽기, 0 기반 주소, 100–60000 ms 반복 간격, 100–10000 ms 응답 대기.
- `ModbusItemDefinition` / `ModbusItemCodec`: 이름·단위·16/32비트 정수·Float32·배율·바이트/워드 순서·값 이름·읽기 전용 속성.
- `ModbusPollingSettings`: 최대 32개 그룹, 전체 8192 raw cell 제한. 서로 다른 ID와 떨어진 주소 범위 구성.
- `ModbusRtuMonitorService`: 직접 쓰기·재조회와 통신 소유권, 불확실한 쓰기의 자동 재전송 방지.
- `ModbusCommandSettings`: 여러 쓰기 단계, 재조회/상태 조건/ACK 확인 방식. 상태 조건에는 비트 마스크가 이미 있음.
- 패킷 분석·원본 로그·시퀀스 RX Check·프로필 저장 기반은 이미 존재한다.

원본 로그가 있다는 것과 시간별 온도·습도 CSV가 있다는 것은 다르다.
명령의 마스크 조건이 있다는 것과 상태 레지스터의 각 비트가 표에 이름으로 표시되는 것도 다르다.
현재 앱에는 범용 Modbus 서버 시뮬레이터, 항목별 트렌드, Modbus TCP 전용 구현을 확인하지 못했다.
시험 보드의 RTU 응답/오류 주입 기능은 범용 앱 시뮬레이터와 구분한다.

또한 현재 그룹 실행기는 유효한 예외 응답을 낸 그룹을 실패 처리하고, 완료 여부가 불확실한
타임아웃/손상 응답에서는 연결을 종료할 수 있다. 쓰기 중복 방지에는 보수적인 설계지만,
한 센서가 간헐적으로 끊기는 장시간 관찰에서는 운영자가 다시 시작해야 하는 제약이 있다.
향후 읽기 전용 요청에 한정한 제한적 재시도·재연결·그룹별 복구 정책을 검토하되,
늦은 응답을 다음 요청의 응답으로 오인하지 않도록 연결 경계와 실패 이력을 보존해야 한다.
불확실한 쓰기는 자동 재전송하지 않는 원칙을 유지한다.

## 추가 개발 우선순위 제안

1. **장치별 레지스터 맵 재사용**: 제조사·모델·펌웨어·문서 버전, 통신 설정과 항목을 한 묶음으로 관리.
   기존 프로필/항목 정의를 확장해 CSV 가져오기·내보내기, 0/1 기반 주소 변환 미리보기, 허용 범위·읽기 전용·예약 주소 검사를 제공한다.
   매번 주소·배율을 다시 입력하는 시간을 줄이는 공통 최우선 과제다.
2. **센서 응답 시뮬레이터**: 에어컨이 클라이언트인 개발에서는 최우선으로 올린다.
   온도 정상/급변/고정, 응답 지연·누락, 예외 응답, 재연결 시나리오를 재현한다.
   PC 호스트 타이밍은 RS-485 전기적 타이밍 시험을 대체하지 않으므로 정밀 시험은 보드와 연계한다.
3. **항목별 추이·CSV·통신 품질**: 온도·압력·밸브 상태를 같은 시간축에 표시하고 유효/과거/실패 상태를 함께 저장.
   응답 시간 분포, 누락률, 연속 오류와 복구 시점을 기록한다. 화면 버퍼는 제한하고 파일 기록은 비동기로 처리한다.
4. **상태 비트 이름과 무효값 처리**: 한 워드의 압축기 운전·제상·센서 오류 비트를 별도로 표시.
   제조사별 무효값을 실제 온도로 해석하지 않도록 하고, 필요하면 배율 외 offset 변환도 지원한다.
5. **제품 회귀 시험 보고서**: 기존 명령·RX Check를 확장해 전원 재기동, 주소/속도 변경, 범위 경계,
   통신 두절·복구의 예상 결과와 실제 결과를 기록. 단순 ACK와 실제 상태 달성을 구분한다.

Modbus TCP는 실제 BMS/게이트웨이 제품이 TCP를 요구할 때 우선순위를 높인다.
기능 코드 수를 늘리기 전에 역할 구분, 장치 맵 재사용, 재현 가능한 실패 시험을 강화하는 편이 이 용도에 더 유용하다.
