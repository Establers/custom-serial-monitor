# v1.6.2 변경 사항

## 시퀀스와 RX Check

- GUI 시퀀스에 별도 RX Check 단계를 추가했습니다. 문자 리터럴과 HEX 패턴을 검사하며, HEX의 `??`는 한 바이트와 일치합니다. 일치하더라도 설정한 검사 시간 전체를 기다립니다.
- 직전 TX 이후 이미 도착한 응답도 같은 회차·연결 범위에서 검사합니다. 연결이 바뀌기 전에 완성된 정상 응답은 유지하고, 이후 연결의 데이터로 미완성 응답을 이어 맞추지 않습니다.
- CP949·UTF-8 문자가 검사 구간의 시작 경계에 걸려도 후행 바이트를 별도 문자로 잘못 매칭하지 않도록 했습니다. 편집 창 취소 시 원본 단계의 모드도 보존합니다.
- 실행 결과 창에서 회차별 송신·일치·미확인·판정 불가 상태, 수신 시각과 원본 RX를 페이지로 확인할 수 있습니다. RX Check가 없는 기존 GUI 시퀀스는 별도 결과 수집 없이 실행합니다.
- 단계 드래그 정렬과 편집·삭제 버튼을 정리했습니다. 기존 JSON은 읽을 수 있으며 RX Check가 포함된 파일은 버전 3으로 내보냅니다. 예전 앱이 검사 패턴을 송신하지 않도록 별도 필드에 저장합니다.
- CLI/MCP는 기존 TX 전용 `CaptureMs`/`Expect` 계약을 유지합니다. GUI RX Check가 포함된 시퀀스의 실행·덮어쓰기는 명시적으로 거부합니다.

## 통신과 장시간 안정성

- 연결·종료·브리지 중지의 취소와 자원 정리 경합을 보완했습니다. 이전 연결의 지연된 TX가 새 연결로 넘어가지 않도록 했습니다.
- 일반 자동화 연결이 포화되어도 취소 요청이 진입할 수 있는 별도 파이프와 실행 한도를 추가했습니다.
- 화면 로그·이벤트·대기 큐에 바이트 기준 메모리 제한을 적용했습니다. 긴 이벤트 문맥은 비동기 디스크 보관과 페이지 조회·전체 내보내기로 처리합니다.
- 수신 누락 구간을 파싱·룰 판정 경계로 전달해, 누락 앞뒤의 데이터로 잘못 일치시키지 않도록 했습니다.
- Terminal 룰 색상을 수신 조각이 아닌 같은 논리 줄 전체에 적용합니다. 키워드가 뒤늦게 도착해도 앞부분을 갱신하고, 화면 메모리 회수·필터 재적용 시에도 색상 상태를 유지합니다.
- Quick CMD와 전송 기록의 연속·앞뒤 공백, HEX 바이트를 보존합니다. TX·검색 기록은 포트별로 분리하고 다중 창 저장 충돌을 병합합니다. 기존 기록 이전 전 백업도 남깁니다.
- 프로필 원자 저장 시 일시적인 파일 공유 잠금은 최대 2초 동안 재시도합니다. 취소·권한 오류는 그대로 전달하고, 최초 저장 중 다른 파일이 생기면 덮어쓰지 않습니다.
- 로그 탐색은 필요할 때 여는 창으로 정리하고 초기 빈 화면·폰트 로딩·크기 변경 중 탐색 회귀를 보완했습니다.

## CLI/MCP 입력과 결과

- 잘못된 인자 이름·자료형·중복 필드·Unicode·손상된 UTF-8을 실행 전에 거부하고, 과대 요청·출력 단절·입력 종료·취소 경합 처리를 보강했습니다.
- MCP 요청 ID 중복 실행을 방지하고 기록 메모리에 한도를 적용했습니다. 대량 저장 명령은 페이지로 조회하며 HEX 캡처의 이어 읽기는 기존 형식을 유지합니다.
- MCP의 stdin 대기를 별도 스레드와 제한된 큐로 분리해 작업 스레드 부족 시의 응답 정지를 방지했습니다. 포화 상태에서도 잘못된 입력을 먼저 검증합니다.
- 한글 JSON 요청·응답이 4,096·8,192바이트 경계에 정확히 맞을 때 파이프가 상대 연결 종료를 기다리던 문제를 수정했습니다. 응답 이후 정리 과정의 추가 쓰기 오류도 보완했습니다.
- 송신 후 결과 알림·정리가 실패해도 이미 전송한 상태와 캡처 증거를 응답에 보존합니다. 결과가 불명확한 TX를 자동 재전송하지 않습니다.

## 설치와 업데이트

- GUI·CLI·인스톨러 버전을 1.6.2로 맞췄습니다. 플러그인만 갱신하면 CLI/MCP 실행 코드 수정은 설치되지 않습니다.
- 플러그인을 1.0.2로 올리고 최신 입력 검증, 캡처 페이지, 시퀀스 제한과 GUI RX Check 구분 안내를 포함했습니다. 최소 CLI 1.6.0·제어 API 1.x 호환은 유지합니다.
- Codex의 `.agents/plugins/marketplace.json`과 Claude Code·Copilot의 `.claude-plugin/marketplace.json`을 원본과 ZIP·프로그램 번들에 함께 제공합니다.
- 배포 전 GUI·CLI·인스톨러 버전, 번들 플러그인 파일과 CLI 호환성을 검사합니다. `-SkipPublish`로 오래된 바이너리나 스킬을 재포장하는 것도 차단합니다.
- 단독 skill은 기존 설치 스크립트를 같은 대상에 다시 실행해야 합니다. 예전 artifacts/빌드 폴더에 고정된 CLI 경로와 수동 MCP 등록도 확인하세요.

## 적용 확인

진행 중인 수집·시퀀스를 마치고 GUI와 MCP를 종료한 뒤 프로그램을 업데이트합니다.
플러그인을 별도로 갱신하거나 단독 skill을 재설치한 후 AI 호스트를 재로드하고 새 세션을 시작하세요.
`serialctl describe --json` 또는 `serial_get_capabilities`의 `data.cliVersion`이
1.6.2인지 확인하고, 실행한 GUI도 같은 프로그램 폴더의 새 버전인지 확인합니다.
`serial_list_instances`와 `serial_get_status` 조회만으로 연결을 점검할 수 있으며 장치 TX는 필요하지 않습니다.

클라이언트별 명령은 [플러그인 가이드](agent_plugins.md)를 참고하세요.

## 배포 파일

- `SerialMonitorSetup.exe`: Windows x64 설치 프로그램
- `SerialMonitorPortable.zip`: 포터블 프로그램과 플러그인 원본
- `SerialMonitorPlugin.zip`: 플러그인 마켓플레이스 원본
- `SerialMonitorSkills.zip`: 기존 단독 skill 설치용
- 각 파일의 SHA-256 체크섬을 함께 제공합니다.

## 검증 범위

- Release 전체: Core 450개, WinUI 1,360개 통과. 장치 환경이 필요한 11개 검사는 기본 실행에서 제외합니다.
- CP949 문자 경계·재연결·편집 취소 회귀: Debug·Release 각각 Core 166개, WinUI 관련 165개 통과.
- 로그 탐색 자동 검사 31건, 실제 Edge 기반 회귀 스크립트 10개 통과.
- STM32 테스트 펌웨어 빌드, C 검사 114건과 독립 프로토콜 계약 검사 81건 통과.
- COM3 실기 기록과 저장된 원본 RX의 수정 전후 판정을 대조했습니다. USB 직접 탈착과 72시간 내구 시험은 이번 검증에 포함하지 않습니다.
