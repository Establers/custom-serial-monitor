# v1.7.0 변경 사항

2026-11-13 배포본입니다. 화면 로그 메모리 예산 설정, Modbus RTU 레지스터 모니터와 직접 쓰기,
시험용 STM32 펌웨어 및 한 번에 실행하는 GUI 테스트 시퀀스를 추가했습니다.

## 화면 로그 메모리

- Settings → UI / xterm의 **Log MiB**에서 보관 데이터 예산을 64–2048MiB로 지정합니다. 기본값은 256MiB이며 프로필에 저장합니다.
- 줄 수·메모리 예산·64Mi 문자 한도 중 먼저 도달하는 한도에 따라 오래된 화면 이력을 제거합니다. 일반 정리는 앞부분만 제거하며 전체 화면을 다시 보내지 않습니다.
- 예산을 낮추면 즉시 정리하고, 높이면 이후 수신분을 더 보관합니다. 이미 제거된 이력은 복원하지 않습니다.
- 부분 RX의 표시·검색 문자열과 버퍼 공유를 개선하고, 보관 한도를 낮출 때 큰 여유 배열도 반환합니다.
- 화면 이력 정리와 파일 로그·룰·시퀀스의 원본 데이터 경로는 독립적입니다. Log MiB는 앱 전체 RAM 사용량의 상한이 아닙니다.

## Modbus RTU 레지스터 모니터

- **Protocol → Modbus RTU → 레지스터 모니터**에서 한 번 읽기와 반복 폴링을 실행합니다. 연결당 장치 하나의 연속 영역 한 개를 감시합니다.
- FC01/02/03/04 읽기, UInt16/Int16/UInt32/Int32/Float32 표시, 배율과 바이트·워드 교환을 지원합니다. 주소는 0 기준 오프셋입니다.
- FC05/06/0F/10으로 단일·복수 코일/레지스터를 쓰고, 응답 확인 후 재조회하여 원시 값이 일치하는지 확인합니다. 쓰기 입력은 표시 배율과 관계없는 원시 값입니다.
- 폴링 중 직접 쓰기는 한 건만 대기하며 진행 중인 쓰기의 주소는 행 선택으로 바뀌지 않습니다. 다른 수동 송신·시퀀스·브리지와 통신 설정 변경은 충돌을 막기 위해 차단합니다.
- timeout·CRC 오류·불완전 응답 등 결과가 불확실하면 원래 연결을 종료합니다. 자동 재연결·폴링 재시작·쓰기 재시도는 하지 않습니다. 정상 형식의 예외 응답이나 쓰기 재조회 불일치는 오류를 표시하고 연결을 유지합니다.
- 설정 저장·재시작·재연결은 폴링이나 쓰기를 자동 시작하지 않습니다. 연결 교체와 잘못된 설정 초안이 이전 값·다른 프로필 설정을 잘못 덮어쓰지 않도록 보강했습니다.

## 시험용 펌웨어와 GUI 시퀀스

- NUCLEO-F103RB 시험 펌웨어 1.7.0은 기존 LAB·BACnet 기능을 유지하고 RAM 쓰기, 변하는 카운터, LD2 코일과 일회성 오류 주입을 제공합니다.
- 펌웨어는 앱 설치로 기록되지 않습니다. 이번 개발에 사용한 보드에는 별도로 기록·읽기 검증을 완료했습니다.
- 실제 보드 자동 검사 24개와 같은 GUI 시퀀스 2회 실행이 통과했습니다. 두 회 모두 52단계 완료, RX Check 26개 일치, 미일치·판정 불가 0개입니다.
- 시험 JSON은 릴리즈 첨부 파일 [03-monitor-extended.gui.json](https://github.com/Establers/custom-serial-monitor/releases/download/v1.7.0/03-monitor-extended.gui.json)에서 받습니다.

### 설치 후 빠르게 확인하기

1. **메모리:** Log MiB를 64 → 256으로 바꾸고 저장·재시작합니다. 수신 중 오래된 화면 로그 정리와 파일 기록의 지속을 확인합니다.
2. **Modbus 폴링:** 시험 보드 COM3 / 115200 / 8N1 / 흐름 제어 없음에 연결합니다. ID 1, FC04, 주소 `0x1000`, 수량 6, UInt32, 배율 1, 교환 꺼짐으로 읽어 카운터 갱신을 확인합니다.
3. **자동 시퀀스:** 폴링·브리지를 중지하고 자동 재연결을 OFF로 설정합니다. Sequences → 시퀀스 관리 → JSON 불러오기에서 위 JSON을 추가합니다.
   **STM32 Modbus Monitor - 확장 레지스터·쓰기·LED·오류 복구**를 선택하고 Run을 누릅니다. 약 19초 뒤 RX Check 26개가 모두 일치해야 합니다.

고의 CRC 손상 단계도 지정된 바이트를 받으면 RX Check는 일치이고 패킷 분석에는 CRC 오류가 표시됩니다.
시퀀스는 시험용 RAM·코일·카운터를 변경하며 정상 완료 시 초기값·LED OFF·조용한 RTU 상태로 돌아갑니다.
FC02의 동적 버튼·CRC 바이트는 GUI 패턴 검사에서 와일드카드를 사용합니다. 전체 CRC·카운터 변화·송신 충돌·재시도 여부는 별도 Live 검증기가 판정합니다.

## 배포와 검증 범위

- GUI·CLI·설치 프로그램 버전은 1.7.0입니다. 설치형·포터블·플러그인·단독 스킬 ZIP과 SHA-256 체크섬을 제공합니다. 플러그인 1.0.3과 CLI/MCP API 1.x 호환을 유지합니다.
- Release 솔루션 빌드 경고·오류 0개, C# 검사 2,631개 통과(장치 조건부 17개 제외), Node 터미널 회귀 29개와 플러그인 호환 검사 22개 통과를 확인했습니다.
- GUI 화면 자동 조작은 수행하지 않았습니다. 실물 통신과 실제 앱의 폴링·시퀀스 실행·RX 판정 경로를 검증했으며, 화면 렌더링·물리 LED 관찰·RS-485 전기 특성·72시간 내구는 별도 확인 범위입니다.
- 업데이트 전 진행 중인 수집·시퀀스를 마치고 앱과 MCP를 종료하세요. 기존 사용자 로그·프로필·제품 메모리와 AI 클라이언트 설정은 유지합니다.
