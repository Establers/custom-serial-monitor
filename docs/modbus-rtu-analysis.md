# Modbus RTU 수신 분석

기존 Inspector 패널의 **Protocol / 프로토콜** 탭에서 `Modbus RTU`를 선택한다.
그 이후 들어오는 실제 RX 원본 바이트와 기존 TX 로그의 원본 바이트를 자동 분석한다.
기본값은 `사용 안 함`이며 선택값은 프로필이나 재시작 때 자동 복원하지 않는다.
이 기능은 장치에 요청을 보내거나 폴링하지 않는다.

## 화면과 보관

- 다른 탭으로 이동하거나 화면 로그를 일시 정지해도 백그라운드 분석은 계속한다.
- 창별로 최근 **10,000개 패킷/분석 조각**을 메모리에 보관한다. 요청과 응답은 각각 한 항목이다.
  따라서 실제 보관 시간은 패킷 수신률에 따라 달라진다.
- 결과 보관에는 별도로 **16 MiB** 예상 메모리 상한도 적용한다. 먼저 닿는 제한에 따라
  오래된 항목을 교체하고 `만료` 수를 표시한다.
  이는 결과 자료구조의 보수적인 추정치이며 프로세스 전체 RAM 한도는 아니다.
- 탭이 보일 때 최대 200 ms 간격으로 UI를 갱신한다. 숨기면 UI 목록 캐시만 비우며
  분석기의 최근 이력과 선택한 ID는 유지한다. 선택한 항목이 아직 보관 중이면 복원한다.
- 패킷 선택 시 원본 HEX, CRC 수신값/계산값, 필드와 레지스터 값을 자세히 보여준다.
  상세 문자열과 레지스터 값 확장은 선택할 때만 수행한다.
- `사용 안 함`은 새 분석을 중지하지만 이미 보관된 결과는 남긴다.
  `분석 목록 비우기`는 이력과 진행 중 조각만 무효화하며 누적 통계는 보존한다.
- 별도의 분석 파일·디렉터리·자동 내보내기는 만들지 않는다. 앱 종료 시 분석 이력은 사라진다.
  기존 시리얼 로그 저장은 기존 설정을 따른다.

## 데이터 경로와 부하 제한

`CaptureBytesReceived`의 기존 불변 RX 배열을 별도 bounded channel에 제공한다.
TX는 기존 `FanOutLogLine`에서 `RawBytes`를 제공한다. HEX 화면 문자열을 재파싱하거나
동일 COM 포트를 다시 열거나 기존 파서의 수신 채널을 경쟁해서 읽지 않는다.
Terminal/HEX 표시 모드와 파일 로깅, 표시 Pause 여부는 RX 분석의 입력을 바꾸지 않는다.
브리지에서 실제 RX는 raw capture observer를 통해 한 번만 제공된다.

입력은 최대 512개 조각 및 합계 4 MiB로 제한한다(처리 중 조각도 바이트 예산에 포함).
초과하면 분석용 조각만 거부하고 누락 조각/바이트를 표시한다. 기존 RX·로그·룰·브리지의
처리를 기다리게 하지 않는다. 누락, 연결 세대 변경, Clear와 분석 재시작 경계에서
조립 중인 프레임을 초기화하여 서로 다른 스트림의 조각을 합치지 않는다.
작업자 예외는 Protocol 상태와 기존 Health 오류 경로에 노출하며 종료 시 취소·회수한다.

## 누적 통계

RX/TX 분석 건수, CRC 정상/오류, 불완전 조각, 미해석 기능, Modbus 예외 응답을
작업자가 결과를 확정할 때 한 번만 집계한다. 탭 전환·스냅샷·오래된 행 만료로 재집계하거나
지우지 않는다. 시작 시각과 마지막 CRC 정상 프레임의 관측 시각도 표시한다.
최초 집계 기준은 창의 분석기 생성 시각이다. 관측 시각은 프레임이 시작된 입력 chunk의
시각을 보존하며, 같은 read 안의 실제 바이트별 선로 시각은 추정하지 않는다. 마지막 CRC
정상 시각은 지연 전달된 과거 데이터 때문에 역행하지 않도록 관측 시각의 최댓값을 쓴다.
`통계 초기화`는 이 카운터 및 누락/보관 만료 카운터를 0으로 돌리고 집계 시작을 갱신한다.
기존 목록은 남기며, 처리 대기 중이던 데이터는 이후 결과가 확정되면 새 집계에 포함된다.

CRC 미확인은 CRC 오류로 세지 않는다. CRC 정상은 의미 검증이나 요청 성공을 뜻하지 않는다.
불완전/미해석 조각의 실제 선로 프레임 수는 알 수 없으므로 RX/TX 숫자는 분석 결과 건수다.
여러 손상 프레임이 경계를 복원할 수 없는 한 조각으로 남으면 그 조각 하나를 불완전으로
집계한다. CRC 오류 수는 길이를 확정한 손상 후보만 집계하며 전체 선로 오류 수의 보장은 아니다.
분석 누락은 패킷 수가 아닌 거부한 입력 **청크/바이트** 수이고 정상 보관 만료와 별개다.

## 해석 범위와 경계의 의미

공개 Modbus V1.1b3 / Serial Line V1.02 규격을 기준으로 직접 구현했다.
일반적인 읽기/쓰기 기능 01–06, 0F, 10과 일부 표준 기능, 예외 응답을 인식한다.
RX의 단일 쓰기처럼 요청과 응답의 형식이 같은 경우 `RequestOrResponse`로 표시한다.
주소가 없는 읽기 응답은 `+0`, `+1`처럼 응답 내 오프셋을 보여주며 시작 주소나
제조사의 단위/배율/32비트 워드 순서를 추측하지 않는다. 자동 요청-응답 연계는 하지 않는다.
CRC가 잘못된 데이터에서는 레지스터 값을 확정하지 않는다.

어떤 USB read 경계나 기존 HEX 화면 한 줄도 RTU 프레임 경계로 단정하지 않는다.
최대 256바이트 버퍼와 기능별 길이/CRC를 사용해 분할 read 및 여러 프레임이 합쳐진
read를 처리한다. 잘못된 CRC 뒤의 정상 프레임은 제한된 범위에서 재동기화한다.
지원하지 않는 기능은 CRC가 일치하더라도 `Undecoded`이며 불완전 데이터와 구별한다.
알려진 전체 길이와 끝 경계가 일치하는 손상 후보는 본문 내부에서 우연히 CRC가 맞는
바이트열을 찾아 정상 요청으로 만들지 않고 그 후보의 CRC 오류로 표시한다. 짧은 요청과
더 긴 응답 후보의 CRC가 모두 맞으면 추가 바이트·끝 경계·뒤따르는 유효 프레임을 함께 본다.
형식을 확정할 수 없는 데이터는 50 ms 조립 대기 또는 버퍼 상한에서 제한된 조각으로
표시한다. 이 50 ms는 호스트 측 조립 대기이지 규격의 t1.5/t3.5 판정값이 아니다.
원본 단조 수신 시각과 native idle 완료 여부를 보존한다. native idle 완료이고 적용된
idle timeout이 설정된 baud/문자 크기의 t3.5 이상인 경우에는 조각 끝에서 조립을 마감한다.
19,200 bps 초과에서는 규격의 1.75 ms 기준을 사용한다. 더 짧은 timeout이나 단순 USB read
경계를 확정 프레임 경계로 취급하지 않는다. 이 메타데이터도 Windows 드라이버 관측 기준이다.
PC/USB 관측만으로 실제 선로의 문자 간격, 충돌, 규격 준수를 증명하지 않는다.

## 확인할 사용 흐름

1. 연결 후 Protocol에서 Modbus RTU 선택. 요청을 전송하지 않고 새 RX가 분석되는지 확인.
2. 정상 요청/응답, CRC 손상, 예외 02를 관측하고 Protocol 행 선택 시 상세를 확인.
3. Search 등 다른 탭에서 통신을 계속한 후 돌아와 새 결과와 기존 선택이 유지되는지 확인.
4. 파일 로그 OFF와 화면 Pause 상태에서도 Protocol 분석이 유지되는지 확인.
5. 10,000개 초과 시 오래된 항목만 만료되고 선택 항목 만료가 표시되는지 확인.
6. 사용 안 함 → 재활성화, Clear, 재연결에서 이전 조각이 새 프레임에 섞이지 않는지 확인.

## 엔진 단독 메모리·처리량 측정

검증용 Release 빌드의 별도 .NET 8 콘솔에서 CRC가 정상인 8바이트 요청으로 측정했다.
10,000개로 준비 후 200,000개를 추가 처리했으며, 최근 보관은 10,000개, 만료는 200,000개,
분석 누락과 입력 대기는 0이었다. 관측 시각 보존을 포함한 최종 코드의 이 PC 한 번 측정에서
경과 약 255 ms / CPU 약 266 ms, GC 후 관리 메모리 약 1.66 MB → 1.74 MB,
결과 보관 추정치 2.64 MB였다(10진 MB).
이는 엔진과 스냅샷 폴링의 합성 입력 측정이다. 실제 UART·드라이버·WinUI 목록/상세 표시의
비용, 잡음/모호한 입력의 처리량이나 다른 PC 성능을 보장하지 않는다.

- 기존 미커밋 변경을 제외한 별도 작업 폴더에서 이번 변경만 적용하여 Release 솔루션 빌드:
  경고 0, 오류 0.
- 최종 전체 자동 검사: Core 505개, WinUI 1,503개 통과. 조건부 검사 11개는 제외됨.
- 분할/합쳐진 read, 중첩 payload와 CRC 후보 충돌, 잘못된 CRC와 예약 주소의 구분,
  qualified native idle 경계, 연결/분석 재시작/Clear/큐 누락 경계, 관측 시각 보존,
  보관 만료와 누적 통계, 숨겨진 탭의 수집·선택 복원을 포함한다.
- 새 화면의 수동 GUI 검증은 사용자 Esc 중단으로 완료하지 않았다. 탭 수명과 선택/보관
  동작은 ViewModel 자동 검사로 확인했다.
