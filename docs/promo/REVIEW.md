# 영상 검토 기록

## 구성과 근거

사용자가 요청한 작은 실제 화면 발췌와 큰 한글 문구를 채택했다. 세 기능을 고르게 보여주는 기능 투어를 선택하고 오류 추적 중심·AI 요청 중심 구성은 제외했다. 설정 화면은 공식 최신 v1.6.4 포터블에서 캡처했다. 실제 RX 성공 장면을 합성하지 않았다.

## 시각 검토

- 장면별 시작·중간 10프레임, 전환 4곳의 전후 20프레임, 360px 축소 시트를 검토했다.
- 별도 시각 검토에서 3·8·13초 전환 첫 프레임이 거의 비는 문제가 발견됐다. 새 장면의 제목과 화면을 처음부터 표시하도록 수정하고 정확한 전환 시각의 스냅샷으로 재확인했다.
- 한글 제목은 작은 화면에서도 읽히고, 설정창 발췌는 사용자 요청대로 작게 유지했다. 본문과 실제 앱의 라벨을 대조했다.
- 가장 약한 장면은 플러그인 설치 명령의 작은 글씨다. 명령 자체를 읽게 하는 용도가 아니므로 큰 문구와 “명령 전송 → 실제 RX 수집 → 수집한 응답 해석” 설명으로 의미를 전달한다. 별도 튜토리얼이라면 설치 안내 대신 실제 제어 녹화를 쓸 수 있다.

## 자동 검사

- HyperFrames `check`: 통과. 린트·런타임·레이아웃 오류 0개, 명암비 38/38 통과.
- 유지한 경고: `film_silent`. README GIF와 동일하게 무음으로 이해하는 구성이므로 의도적이다. 내레이션·음악은 넣지 않았으며 청음 검사는 해당하지 않는다.
- GIF 변환 스크립트: Node 구문 검사 및 실제 변환 통과.

## 최종 파일 측정

- MP4: H.264 / yuv420p, 1920×1080, 30 fps, 600프레임, 20.000초, 1,445,307바이트.
- GIF: 960×540, 240프레임, 20.000초, 1,290,177바이트. GIF의 1/100초 시간 단위에 맞춰 12 fps의 프레임 지연을 교대로 기록한다.
- 로컬 렌더: Chrome headless shell 152, AMD 하드웨어 GPU, screenshot 캡처, 약 21초 소요.
- MP4와 GIF 전체 프레임 디코딩에서 오류가 없었다. MP4의 장면별 디코딩 프레임과 GIF의 5.5초 프레임을 시각적으로 확인했다. GIF 무한 반복 메타데이터와 README·원본의 로컬 자산 링크도 검사했다.
- 후속 편집은 번들 HTML 원본 또는 [HyperFrames 데스크톱 앱](https://hyperframes.studio/studio/download?os=windows&src=cli)에서 이어갈 수 있다.
