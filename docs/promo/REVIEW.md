# 영상 검토 기록

## 구성과 근거

사용자가 요청한 작은 실제 화면 발췌와 큰 한글 문구를 채택했다. 세 기능을 고르게 보여주는 기능 투어를 선택하고 오류 추적 중심·AI 요청 중심 구성은 제외했다. 설정 화면은 공식 최신 v1.6.4 포터블에서 캡처했다. 실제 RX 성공 장면을 합성하지 않았다.

## 시각 검토

- 장면별 시작·중간 10프레임, 전환 4곳의 전후 20프레임, 360px 축소 시트를 검토했다.
- 최초 무음 버전의 별도 시각 검토에서 3·8·13초 전환 첫 프레임이 거의 비는 문제가 발견됐다. 새 장면의 제목과 화면을 처음부터 표시하도록 수정했고, 내레이션 버전에서도 변경된 전환 시각을 재확인했다.
- 한글 제목은 작은 화면에서도 읽히고, 설정창 발췌는 사용자 요청대로 작게 유지했다. 본문과 실제 앱의 라벨을 대조했다.
- 가장 약한 장면은 플러그인 설치 명령의 작은 글씨다. 명령 자체를 읽게 하는 용도가 아니므로 큰 문구와 “명령 전송 → 실제 RX 수집 → 수집한 응답 해석” 설명으로 의미를 전달한다. 별도 튜토리얼이라면 설치 안내 대신 실제 제어 녹화를 쓸 수 있다.

## 내레이션 추가 후 검사

- HyperFrames `check`: 통과. 린트·런타임·레이아웃·오디오 오류와 경고 0개, 명암비 40/40 통과.
- 사용자가 제공한 MP3 5개를 원본 체크섬 그대로 보관했다. 전체 길이 21.997초에서 파일 가장자리의 무음 0.168초를 정리하고, `atempo=1.12`로 음높이를 유지하며 말속도를 조정했다. 구간별 2회 음량 보정 후 하나의 20초 WAV로 연결했다.
- 실제 보정 음성은 각 장면보다 짧으며, 구간 말미에 52–185ms를 남겨 음성을 잘라내지 않는다. 도입부에 80ms 여유를 둔다. 영상 장면은 0·2.333·7.433·12.267·16.267초에 시작하며, 엔딩은 3.733초로 늘렸다.
- 음성 WAV 측정: -16.2 LUFS, 실제 피크 -1.5 dBTP, 클리핑 0회. 마지막 0.25초는 무음이다. 음질과 문장 발음은 직접 청음하지 않았으며 음량과 신호를 측정했다.
- 렌더러가 모노를 동일한 두 채널로 확장해 MP4 음량이 3 LU 상승하는 것을 측정했다. 최종 음성 트랙에 -3 dB 게인을 적용해 영상 음량을 보정했다.
- 수정한 5개 장면의 시작·중간, 전환 4곳의 전후, 360px 축소 시트를 재검토했다. 중요한 제목은 전환 직후부터 보이고 마지막 문구는 2초 이상 유지한다.
- GIF 변환 스크립트: Node 구문 검사 및 실제 변환 통과.

## 최종 파일 측정

- MP4: H.264 / yuv420p, 1920×1080, 30 fps, 600프레임, AAC 48kHz 2채널, 20.000초, 1,929,593바이트. 오디오와 비디오는 모두 0초에 시작하고 정확히 20초다.
- 최종 MP4 오디오: -16.2 LUFS, 실제 피크 -4.5 dBTP, 클리핑 0회. 다섯 구간 각각을 WAV 기준과 비교해 신호 상관도 0.99997 이상으로 음성 내용과 배치가 보존됐음을 확인했다.
- GIF: 960×540, 240프레임, 20.000초, 1,331,868바이트. GIF의 1/100초 시간 단위에 맞춰 12 fps의 프레임 지연을 교대로 기록한다.
- 로컬 렌더: Chrome headless shell 152, AMD 하드웨어 GPU, screenshot 캡처, 약 21초 소요.
- MP4와 GIF 전체 프레임 디코딩에서 오류가 없었다. MP4의 전환 전후 및 장면별 디코딩 프레임과 GIF의 룰 장면을 시각적으로 확인했다. GIF 무한 반복 메타데이터, 원본 MP3 체크섬, 타임라인과 대사의 프레임 배분, README·원본의 로컬 자산 링크 51개도 검사했다.
- 후속 편집은 번들 HTML 원본 또는 [HyperFrames 데스크톱 앱](https://hyperframes.studio/studio/download?os=windows&src=cli)에서 이어갈 수 있다.
