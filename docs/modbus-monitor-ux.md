# 장치 감시·제어 UI 기준

## 기본 흐름

사용자는 **읽기 설정 → 현재 값 읽기 → 자동 읽기** 순서로 시작한다.
읽을 범위는 장치 ID, 데이터 종류(FC), 시작·끝 주소, 개수로 표시한다.
`0 + 10` 같은 내부 표기 대신 `주소 0–9 (10개)`를 쓴다.
주소는 Modbus 프로토콜의 0 기반 주소이며 10진수와 `0x` HEX를 받는다.

- **읽기 설정**: 장치 ID·읽을 데이터·시작 주소·개수가 먼저다. 반복 간격과 응답 대기는 ms 단위를 붙인다.
- **현재 값 읽기**: 현재 설정한 주소 범위 전체를 한 번 읽는다. 툴팁에도 실제 범위를 표시한다.
- **자동 읽기 시작**: 응답 후 설정한 간격만큼 기다렸다가 다시 읽는다. 중지하면 마지막 값을 남긴다.
- **값 쓰기**: 표에서 행을 고르고 주소·값을 확인한 뒤 장치에 쓴다. 쓰기 후 재조회로 확인하며 자동 재전송하지 않는다.
- **이름·단위 설정**: 주소별 이름·단위·자료형·배율을 지정한다. 자료형·바이트 순서 같은 세부 설정은 접어서 둔다.

## 여러 범위 읽기

읽기 그룹은 이름을 붙인 장치 ID와 주소 범위다. 장치 하나의 떨어진 주소 범위도 여러 그룹으로 나눌 수 있다.
드롭다운은 **표에 표시할 그룹**을 선택한다. **선택 그룹 읽기**는 그 그룹만 한 번 읽는다.
**자동 읽기 (N개 그룹)**는 `자동 읽기에 포함`한 모든 그룹을 차례로 읽는다.
버튼 툴팁에는 포함된 그룹 이름과 범위를 나열한다. 포함 그룹이 없으면 시작할 수 없다.
선택한 그룹의 포함 여부는 읽기 설정에서 바꿀 수 있고, 읽는 중에는 변경할 수 없다.

설정 편집·적용·저장은 송신을 시작하지 않는다. 이 동작 원칙은 유지하되,
화면의 초기 상태에는 부정문 대신 **읽기 전**과 다음 행동을 안내한다.
아직 읽지 않은 행을 `응답 대기`로 표시하지 않는다. 읽는 중, 응답 확인 실패,
연결 끊김, 읽기 중지, 최신 값, 과거 값을 구분한다.
표는 주소 → 이름 → 값 → 원본 HEX → 상태 → 마지막 응답 순서로 배치한다.

## 공통 디자인과 문구

기준은 [공통 폼 배치](modbus-numeric-field-layout.md)와
`SerialMonitor.WinUI/Resources/CompactControlStyles.xaml`이다.

- 버튼·선택칸·펼침 메뉴는 기존 Modbus 공통 스타일을 사용한다. 높이·화살표·패딩을 화면마다 다시 만들지 않는다.
- 기본 조작은 짧은 동사형으로 적고, 실제 작업 범위는 바로 옆 요약과 툴팁에 표시한다.
- `대상`, `활성`, `폴링`만으로 사용자의 행동을 설명하지 않는다. 읽기 범위, 자동 읽기에 포함, 자동 읽기를 사용한다.
- 한국어 설명은 짧은 행동 안내로 쓴다. 내부 잠금·예약·적용 경계 설명은 필요한 도움말에 둔다.
- 새 탭이나 상시 설명 영역을 쌓지 않는다. 초기 안내는 값이 들어오면 숨기고, 상세 옵션은 공통 펼침 메뉴에 둔다.
- 오류는 통신 상태에 우선 표시한다. 연결 제약과 이전 값의 상태를 숨기지 않는다.
- 설정·그룹을 불러오기만 해서는 TX하지 않는다. 읽기 범위가 바뀌면 이전 장치의 쓰기 초안을 재사용하지 않는다.

## 검증 기준

관련 빌드·회귀 테스트에 더해 실제 WinUI 화면에서 설정 → 읽기 → 자동 읽기 → 중지 → 쓰기를 확인한다.
800×600과 일반 창 크기에서 공통 레이아웃 검사로 잘림·스크롤·입력칸 정렬을 확인한다.
장비 실기와 모의 테스트의 결과를 구분하고, COM 설정·펌웨어 빌드 ID·원본 RX 근거를 남긴다.
