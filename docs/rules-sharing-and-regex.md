# 로그 룰 공유와 정규식

Rules 상단에서 **룰 추가 / 내보내기 / 가져오기**를 사용한다. 기존 행의 편집·삭제·색상 변경도 유지한다.

## 복사·붙여넣기로 공유

1. **내보내기**를 누르면 전체 룰의 공유 텍스트가 열린다. 선택한 행만 전달하려면 **선택한 룰만 내보내기**를 켠다.
2. **복사**를 눌러 메신저 등에 전달한다. 받는 쪽에서는 **가져오기**를 열어 빈 칸에 붙여넣는다.
3. 검사된 룰 수를 확인하고 **가져오기**를 누른다. 기존 룰은 유지하며 설정이 완전히 같은 룰은 건너뛴다.
   이름이 같아도 설정이 다르면 별도 룰로 추가한다. 오류가 있으면 전체를 반영하지 않는다.

공유 텍스트는 `SMRULES:1:`로 시작하는 버전이 있는 코드다. 실제 로그, 포트 설정, 프로필 전체,
명령 시퀀스의 내용은 포함하지 않는다. 룰의 이름·패턴·모드·방향·대소문자·색상·우선순위·알림 등은 보존한다.
최대 200개, 텍스트 1,000,000자까지 지원한다. 중간 줄바꿈과 앞뒤 공백은 허용하며 코드를 수정할 필요는 없다.

시퀀스 연결 이름은 함께 전달하지만 해당 룰은 **꺼진 상태로 추가**한다. 받는 PC에 같은 이름의 다른 명령이
있을 수 있으므로 편집창에서 RX trigger sequence의 연결 내용을 확인한 뒤 켠다. 룰 저장은 기존 프로필 저장을 따른다.

## Terminal 줄 단위 매칭

일반 문자열 룰도 **화면에서 이어지는 같은 RX 줄**을 검사한다. `prefix te` / `mp=4` / `2 suffix`처럼
내부에서 나누어 받아도 `temp=42`가 이벤트·강조·필터 모두에서 일치한다. 일치하는 문자열이 도착하면
이벤트가 발생하고 줄 전체가 강조된다. 필터는 보관 중인 앞부분과 이후 도착한 조각을 함께 표시한다.
필터를 나중에 켜거나 다시 적용해도 같은 기준을 사용하며, 화면 보관·긴 줄 제한은 유지한다.
개행·연결 변경·모드 변경·수신 누락으로 구분된 줄은 합치지 않는다. 화면 폭에 따른 자동 줄바꿈은
매칭을 나누지 않으며, TX 문자열은 RX 패턴에 섞이지 않는다.

## HEX 줄 단위 매칭

HEX 모드는 원시 바이트 패턴을 사용한다. 잘못된 HEX 입력은 편집창에서 저장할 수 없다.

HEX 룰은 **화면에서 이어지는 같은 RX 줄**의 바이트를 검사한다. 예를 들어 `DE AD` 뒤에 `BE EF`가
나누어 도착해 같은 줄에 표시되면 `DE AD BE EF` 룰이 이벤트·강조·필터 모두에서 일치한다.
큰 수신 묶음이 내부 64 KiB 조각으로 나뉘어도 동일하다. 타임아웃으로 구분된 다음 수신 줄,
연결·모드 변경, 수신 누락을 가로질러 붙이지 않는다. 화면 폭에 따른 자동 줄바꿈은 룰을 나누지 않는다.
TX 바이트는 RX 패턴에 섞이지 않으며 TX는 송신 기록 단위로 검사한다.

나중 조각에서 HEX 룰이 일치해도 같은 줄의 앞부분까지 강조한다. HEX 필터는 보관 중인 앞부분과
일치 이후 도착한 조각도 함께 표시한다. 화면의 기존 보관·긴 줄 제한은 유지한다.
검사용으로는 패턴 길이보다 짧은 바이트 꼬리만 유지하므로 개행 없는 수신 전체를 누적하지 않는다.

## 정규식

룰 편집창에서 Terminal 모드를 고르고 **정규식 (Regex)**을 켠다. 기본값은 기존의 문자열 포함 검색이다.
정규식은 Terminal 전용이며 잘못된 패턴은 편집창에서 저장할 수 없다.

| 예시 | 의미 |
| --- | --- |
| `ERROR\|WARN` | ERROR 또는 WARN |
| `temp=\d+` | temp= 뒤에 숫자 한 개 이상 |
| `^READY$` | 줄 전체가 READY |
| `error=[0-9A-F]{2}` | 두 자리 오류 코드 |

정규식은 **완성된 Terminal 줄**을 검사한다. RX가 여러 조각으로 들어와도 줄 끝까지 합쳐서 검사하며,
조각 사이의 TX는 RX 문자열에 끼워 넣지 않는다. TX는 송신 기록 단위로 검사한다. 서로 다른 RX 줄은 합치지 않는다.
개행 없이 계속 들어오는 RX는 줄이 끝나기 전에는 정규식 이벤트·강조·필터가 적용되지 않는다.
일반 키워드 룰은 기존처럼 새 문자열이 도착하는 즉시 검사한다.
일반 문자열 필터와 정규식 필터를 함께 선택해도 같은 줄의 앞뒤 내용을 중복하거나 누락하지 않는다.

안정성을 위해 정규식은 1,024자, 검사할 줄은 16,384자로 제한한다. 더 긴 줄은 그 줄의 끝까지 건너뛰고
다음 줄부터 다시 검사한다. 수신 누락 등으로 줄의 앞부분을 알 수 없으면 남은 조각을 새로운 줄로 오인하지 않는다.
연결·모드 변경이나 데이터 누락 경계에서는 다음 개행까지 정규식 검사를 건너뛰어 줄 경계를 다시 맞춘다.
화면 보관 범위를 벗어난 로그 전체를 필터가 복원하지는 않는다.

선형 시간 엔진과 25ms 실행 제한을 사용한다. 전후방 탐색(lookaround)과 역참조(backreference)는 지원하지 않는다.
길이가 0인 일치는 이벤트를 만들지 않는다. 실행 제한을 넘긴 패턴은 해당 실행본에서 중단하고 오류를 표시한다.
패턴을 수정·재적용하면 다시 검사한다. 이 제약은 [.NET 정규식 옵션](https://learn.microsoft.com/en-us/dotnet/standard/base-types/regular-expression-options)에 따른다.

## 기존 동작 수정

- 문자열·정규식 패턴의 앞뒤 공백을 저장·불러오기에서 보존한다. 예를 들어 ` ERROR `와 `ERROR`는 다른 조건이다.
- 필터 식별에도 공백과 정규식 사용 여부를 포함한다. 대소문자를 구분하지 않는 정규식이라도 `\d`와 `\D`를 같은 룰로 취급하지 않는다.
- 잘못된 프로필 패턴은 경고와 함께 비활성화하여 보존한다. 편집해서 수정할 수 있다.
- 수신 조각·줄 종료·버퍼 제거·비동기 필터 재구성에서 이벤트/강조/필터의 결과를 회귀 검사한다.

## 수동 확인

- 밝은/어두운 테마와 800×600 창에서 기존 편집창, 정규식 도움말, 내보내기·가져오기 팝업이 잘리지 않는지 확인한다.
- 전체/선택 룰 내보내기 → 복사 → 가져오기 후 색상·알림·대소문자·우선순위를 비교한다.
- 같은 코드를 두 번 가져와 중복이 늘지 않는지 확인한다. 일부를 지운 코드와 다른 버전의 코드는 반영하지 않아야 한다.
- `^temp=\d+$` 룰에 `temp=`와 `42`를 나누어 수신하고 개행한다. 줄이 완성됐을 때 한 번만 매칭돼야 한다.
- `^READY$`에 `READY` 후 `X` 후 개행을 수신한다. 미완성 `READY` 조각만으로 매칭되면 안 된다.
- 일반 문자열의 ` ERROR `를 저장하고 프로필을 다시 불러와 공백이 보존되는지 확인한다.
- Terminal의 `temp=42` 룰에 `prefix te` / `mp=4` / `2 suffix` / ` tail`을 나누어 수신한다.
  `prefix temp=42 suffix tail` 전체가 강조·필터되고, 필터 재적용 후에도 같은 내용이 보여야 한다.
- HEX의 `DE AD BE EF` 룰에 같은 수신 줄의 `10 DE AD` / `BE EF 20` / `30`을 나누어 넣는다.
  이벤트가 한 번 발생하고 전체 줄이 강조되며 필터에서도 `10 DE AD BE EF 20 30`이 보여야 한다.
  두 조각 사이에 수신 줄 구분이나 데이터 누락이 있으면 일치하지 않아야 한다.

## 자동 검사

`TerminalStreamingRuleTests`, `HexStreamingRuleTests`, `RegexLogRuleTests`, `LogRuleTransferTests`는
분할 RX·실제 개행·수신 누락·화면 보관 한도·필터 재구성·
룰 변경·잘못된 패턴·공유 텍스트 왕복을 검사한다. 실제 장치 연결이나 장시간 UART 시험을 대신하지 않는다.

팝업은 다음 명령으로 1280×900 / 800×600, 밝은/어두운 테마에서 확인할 수 있다.
편집·잘못된 정규식 오류·전체/선택 룰 내보내기·잘못된/정상 텍스트 가져오기를 포함하며,
클립보드나 프로필을 변경하지 않는다.

```powershell
$env:SERIAL_DIALOG_SCREENSHOTS = '1'
./scripts/test_modbus_layout_native.ps1 `
  -AppPath ./SerialMonitor.WinUI/bin/x64/Release/net8.0-windows10.0.19041.0/win10-x64/SerialMonitor.WinUI.exe `
  -OutputDirectory ./artifacts/rules-ui -CaseFilter rules
```
