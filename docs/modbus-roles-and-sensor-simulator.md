# Modbus 역할과 센서 시뮬레이터

## 어떤 역할을 선택하나요?

| 개발 상황 | 앱에서 선택 | 이 PC의 동작 |
| --- | --- | --- |
| 에어컨과 실제 센서가 주고받는 내용을 확인 | 통신 관찰 (기본값) | 수신·분석만 수행. 이 연결의 수동 TX, 시퀀스, AI 송신도 차단 |
| 에어컨 대신 PC로 실제 센서의 값을 읽거나 설정 | 장치 직접 시험 | 읽기·쓰기 버튼을 누르면 PC가 요청 전송 |
| 실제 센서 없이 에어컨의 통신을 시험 | 센서 시뮬레이터 | 시작 후 요청을 기다렸다가 JSON에 정의된 값으로 응답 |

역할을 선택하거나 JSON을 불러오는 것만으로는 송신하지 않는다. 실행 중인 직접 시험이나
시뮬레이터를 중지한 뒤 역할을 바꾼다. 앱을 다시 열면 통신 관찰로 시작하며 자동 응답을 복원하지 않는다.
일반 UART 수동 TX·시퀀스는 역할 메뉴의 기존 **사용 안 함**(프로토콜 분석 끔)에서도 사용할 수 있다.

통신 관찰에서 RX는 PC가 수신했다는 뜻이다. 에어컨의 요청과 센서의 응답이 모두 RX로 들어올 수 있다.
장치 직접 시험은 기존 에어컨 마스터를 중지한 버스에서 사용한다. 센서 시뮬레이터는 대신할 실제
센서를 분리하고 에어컨의 요청을 받도록 연결한다. 동일 ID 센서 두 대를 함께 응답시키지 않는다.

## PDF → AI → 앱

1. 센서 시뮬레이터 화면의 **AI 작성 지침 복사**를 누른다.
2. 다른 AI에 제조사 PDF와 복사한 지침을 함께 주고 `.json` 파일을 받는다.
3. **JSON 파일…**로 불러온다. 또는 JSON 입력칸에 붙여 넣고 **JSON 확인**을 누른다.
4. 미리보기에서 장치 ID, 기능 코드, 주소 범위, 자료형·배율과 값을 PDF와 대조한다.
5. 상단에서 포트와 통신 설정을 맞추고 연결한 뒤 **센서 응답 시작**을 누른다.
6. 에어컨이 요청하면 응답 횟수가 증가한다. 요청이 없으면 송신하지 않는다.

[AI 작성 지침](modbus_sensor_authoring.md), [JSON Schema](modbus_sensor.schema.json),
[기초 연습 예제](modbus_sensor_example.json)를 함께 제공한다. 기초 예제는 실제 제품 사양이 아니다.
화면의 **EE071 예제**는 [E+E EE071 공식 문서 기반 온습도 읽기 예제](modbus_sensor_ee071.md)를 불러온다.
제조사 전체 동작을 재현하는 예제는 아니며, 초기값·지원 범위·출처를 미리보기에 표시한다.
JSON 파일의 문법·주소 중복·값 변환 검사는 앱이 수행하지만, PDF의 주소를 AI가 정확히 옮겼는지는
사람이 확인해야 한다. 이 파일은 센서 시뮬레이터 입력용이며 직접 시험의 읽기 그룹 파일과 다르다.

## 이번 버전의 범위

- 센서 ID 하나, FC01–04 읽기, FC05/06/15/16 쓰기, 초기값과 0–1000ms 응답 지연.
- 16/32비트 정수와 Float32, 배율, 바이트/워드 순서. 읽기 전용 주소의 쓰기는 거절.
- 쓰기 결과는 실행 중 메모리에 반영. 중지 후 다시 시작하면 JSON의 초기값으로 복원.
- JSON 수정은 중지 후 가능. 값의 자동 변화, 오류·무응답 주입, 제조사별 부작용은 지원하지 않음.
- 수신 대기열은 64개 청크·64KiB로 제한하고 초과 시 응답을 중지. 연결 변경·취소 시 수신 구독과 독점 사용을 해제.
- 어댑터 로컬 에코를 꺼야 한다. FC05/06 응답과 동일한 패킷이 100ms 안에 돌아오면 응답 순환을 막기 위해 중지한다.
- USB/Windows 기반이므로 정밀 RTU 타이밍 적합성 검사용은 아니다.

## 센서 재검토 및 EE071 예제 검증 — 2026-11-15

- 가변 길이 요청처럼 보이는 잡음 뒤에 정상 요청이 붙으면, 길이를 계속 기다리다 정상 요청까지
  버리는 결함을 재현했다 (`artifacts/sensor-audit/red-test.log`: 수정 전 타임아웃 실패).
  실제 수신의 idle 경계에서 불완전한 앞부분을 버리며 CRC가 맞는 뒤쪽 요청을 복구하도록 수정했다.
  정상 다중 쓰기의 데이터 안에 CRC-valid 패킷이 들어 있어도 분할 수신 중에는 꺼내지 않는 검사도 추가했다.

  앱의 요청 생성기와 독립적으로 계산한 고정 요청·응답 벡터로 예제 파일 자체를 검사한다.
- 최종 Release 빌드: 경고 0, 오류 0 (`artifacts/sensor-audit/build.log`).
- Core Modbus: 186 통과 (`artifacts/sensor-audit/core.trx`).
