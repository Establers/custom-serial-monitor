# Modbus 역할과 장치 시뮬레이터

## 어떤 역할을 선택하나요?

| 개발 상황 | 앱에서 선택 | 이 PC의 동작 |
| --- | --- | --- |
| 마스터와 슬레이브가 주고받는 내용을 확인 | 통신 관찰 (기본값) | 수신·분석만 수행. 이 연결의 수동 TX, 시퀀스, AI 송신도 차단 |
| PC를 마스터로 사용해 실제 장치의 값을 읽거나 설정 | 장치 직접 시험 | 읽기·쓰기 버튼을 누르면 PC가 요청 전송 |
| 실제 슬레이브 없이 마스터의 통신을 시험 | 장치 시뮬레이터 | 시작 후 요청을 기다렸다가 JSON에 정의된 값으로 응답 |

역할을 선택하거나 JSON을 불러오는 것만으로는 송신하지 않는다. 실행 중인 직접 시험이나
시뮬레이터를 중지한 뒤 역할을 바꾼다. 앱을 다시 열면 통신 관찰로 시작하며 자동 응답을 복원하지 않는다.
일반 UART 수동 TX·시퀀스는 역할 메뉴의 기존 **사용 안 함**(프로토콜 분석 끔)에서도 사용할 수 있다.

통신 관찰에서 RX는 PC가 수신했다는 뜻이다. 마스터의 요청과 슬레이브의 응답이 모두 RX로 들어올 수 있다.
장치 직접 시험은 기존 마스터를 중지한 버스에서 사용한다. 장치 시뮬레이터는 대신할 실제
장치를 분리하고 마스터의 요청을 받도록 연결한다. 동일 ID 장치 두 대를 함께 응답시키지 않는다.

## 제품의 통신 자료 → AI → 앱

1. **제품 관리 → AI로 제품 정의 만들기…**를 연다. 간단한 안내를 읽고 **AI 지침 + JSON 예제 복사**를 누른다. 성공/실패는 이 창 안에 표시된다.
2. 다른 AI에 제품의 통신 프로토콜 자료(통신 설명서·레지스터 맵·요청/응답 예제)와 복사한 지침을 함께 주고 `.json` 파일을 받는다.
3. **제품 관리 → JSON 불러오기…**로 추가한다. 직접 붙여 넣으려면 **새 제품… → 목록에 저장**을 누른다. 저장할 때 자동으로 검사한다.
4. 미리보기에서 장치 ID, 기능 코드, 주소 범위, 자료형·배율과 값을 원본 자료와 대조한다.
5. 상단에서 포트와 통신 설정을 맞추고 연결한 뒤 **응답 시작**을 누른다.
6. 마스터가 요청하면 응답 횟수가 증가한다. 요청이 없으면 송신하지 않는다.

[AI 작성 지침](modbus_sensor_authoring.md), [JSON Schema](modbus_sensor.schema.json),
[기초 연습 예제](modbus_sensor_example.json)를 함께 제공한다. 기초 예제는 실제 제품 사양이 아니다.
제품 목록의 **EE071 · 기본 예제**는 [E+E EE071 공식 문서 기반 온습도 읽기 예제](modbus_sensor_ee071.md)를 불러온다.
제조사 전체 동작을 재현하는 예제는 아니며, 초기값·지원 범위·출처를 미리보기에 표시한다.
JSON 파일의 문법·주소 중복·값 변환 검사는 앱이 수행하지만, 통신 자료의 주소를 AI가 정확히 옮겼는지는
사람이 확인해야 한다. 이 파일은 장치 시뮬레이터 입력용이며 직접 시험의 읽기 그룹 파일과 다르다.

## 제품 관리

- 시작 화면에서는 제품을 선택하고 주소·초기값을 확인한다. JSON 편집기는 **제품 관리 → 제품 편집**에서 연다.
- **새 제품 / JSON 불러오기 / JSON 내보내기 / 제품 편집 / 제품 복제 / 제품 삭제 / 목록 새로 고침 / AI로 제품 정의 만들기**를 한 메뉴에 모았다.
- 사용자 제품은 `%LOCALAPPDATA%/SerialMonitor/modbus-devices`에 개별 JSON으로 저장한다. 최대 128개, 파일당 256 KiB다. 다음 실행에서도 목록을 읽지만 자동 응답은 시작하지 않는다.
- EE071은 항상 제공하는 읽기 예제다. 기본 예제는 삭제하거나 덮어쓰지 않으며 편집하면 사용자 복사본을 만든다.
- 저장 시 문법·주소·초기값 검사를 통과해야 목록에 반영한다. 실패하면 편집 내용을 그대로 두고 이유를 표시한다. 다른 창에서 변경한 파일은 덮어쓰지 않고 새로 고침을 안내한다.
- 표의 **시작할 때 값**은 초기값이다. 마스터의 쓰기로 바뀐 실행 중 값은 이 표에 표시하지 않는다.
- 센서 외에도 계측기·릴레이·제어기 등의 비트/레지스터 맵을 정의할 수 있다. 모든 Modbus 기능을 구현한 것은 아니다. **지원 기능**에서 범위를 확인한다.

## 이번 버전의 범위

- 장치 ID 하나, FC01–04 읽기, FC05/06/15/16 쓰기, FC22 마스크 쓰기, FC23 쓰기 후 읽기, 초기값과 0–1000ms 응답 지연.
- 16/32비트 정수와 Float32, 배율, 바이트/워드 순서. 읽기 전용 주소의 쓰기는 거절.
- 코일/입력 비트를 지원한다. 진단, 장치 식별, 파일, FIFO, 사용자 정의 기능과 문자열 자료형은 지원하지 않는다.
- 쓰기 결과는 실행 중 메모리에 반영. 중지 후 다시 시작하면 JSON의 초기값으로 복원.
- JSON 수정은 중지 후 가능. 값의 자동 변화, 오류·무응답 주입, 제조사별 부작용은 지원하지 않음.
- 수신 대기열은 64개 청크·64KiB로 제한하고 초과 시 응답을 중지. 연결 변경·취소 시 수신 구독과 독점 사용을 해제.
- 어댑터 로컬 에코를 꺼야 한다. FC05/06/22 응답과 동일한 패킷이 송신 중 또는 송신 완료 후 100ms 안에 수신되면 응답 순환을 막기 위해 중지한다. 응답 지연 중 송신 전에 수신한 재요청은 에코로 처리하지 않는다.
- 미지원 표준 단축 요청(FC07/11/12/17/24 및 FC43의 장치 식별 MEI 14)은 `Illegal Function` 예외로 응답한다. 해당 기능의 실제 동작을 구현한 것은 아니며, 다른 장치 ID·브로드캐스트·CRC 오류에는 응답하지 않는다.
- USB/Windows 기반이므로 정밀 RTU 타이밍 적합성 검사용은 아니다.

## RTU 타이밍과 추가 레지스터 기능

- 응답을 쓰기 전에 마지막 수신 알림부터 t3.5 이상 기다린다. 19200 baud 이하는 3.5문자 시간,
  그보다 빠르면 1.75ms를 기준으로 한다. 표준 11비트/문자보다 긴 설정은 실제 설정 길이를 사용한다.
  직전 응답의 예상 전송 시간과 프레임 간격도 계산해 연속 요청에 대한 응답을 붙여 보내지 않는다.
  `responseDelayMs=0`도 이 간격을 생략하지 않는다. 수신이 더 들어오면 대기 기준을 갱신하며 중지/연결 변경 시 송신하지 않는다.
- 이는 **호스트에서 확보하는 최소 대기**다. Windows 스케줄링과 USB 버퍼 때문에 실제 응답은 더 늦어질 수 있고,
  수신 바이트 사이의 t1.5 위반, 정확한 선로 프레임 경계, RS-485 트랜시버 방향 전환을 검증하거나 보장하지 않는다.
  기존 수신 완료 알림/CRC 기반 조립은 유지한다. 정밀 규격 적합성 시험에는 하드웨어 타이밍 측정이 필요하다.
- FC22(10진수, HEX 0x16)는 `area=3, writable=true`인 레지스터를 AND/OR 마스크로 변경하고 요청을 그대로 응답한다.
  브로드캐스트 쓰기는 반영하지만 응답하지 않는다.
- FC23(10진수, HEX 0x17)은 읽기 최대 125개·쓰기 최대 121개를 지원한다. 두 범위를 먼저 검사해 실패 시 값을 바꾸지 않는다.
  쓰기 후 읽으므로 범위가 겹치면 새 값을 반환한다. 읽기를 포함한 브로드캐스트 요청은 처리하지 않는다.
- JSON v1의 기존 `points`를 그대로 사용한다. 읽기 전용 EE071 예제의 주소를 임의로 쓰기 가능하게 바꾸지 않는다.
- 기준: [Modbus Serial Line V1.02 §2.5.1](https://www.modbus.org/file/secure/modbusoverserial.pdf),
  [Application Protocol V1.1b3 §6.16–6.17](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf).
