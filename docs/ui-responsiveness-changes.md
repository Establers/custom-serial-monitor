# UI 응답성 개선 및 검증 — 2026-11-13

기존 동작을 보존하면서 중복 작업을 줄이는 첫 세 항목만 적용했다.

## 변경 범위

1. **상태 표시:** 1초 타이머의 제어선 UI 상태가 같으면 속성 알림을 생략한다.
   드라이버 상태뿐 아니라 연결, 출력 모드, 설정값, 편집 가능 여부, 작업 중 상태,
   오류 안내를 비교한다. 설정 변경·거절된 편집 복원·연결 수명 주기의 명시적 갱신은
   계속 알린다. 명시적 갱신은 추가 속성 조회 없이 기존 알림을 유지하고 다음
   타이머에서 비교 기준을 새로 잡는다. 드라이버 폴링 주기와 화면의 1초 확인 주기는 유지한다.
2. **크기 맞춤:** 기존 50ms 대기 구간 전체에 걸쳐 중복 요청을 합친다.
   WebView 호출 전에 대기 표시를 해제하므로 호출 중 들어오는 마지막 크기 변경도
   후속 요청으로 반영할 수 있다. 디스패처가 요청을 거절하면 대기 표시를 해제한다.
   xterm 자체 줄바꿈 재계산, 글꼴, 화면 이력 보관 정책은 유지한다.
3. **메뉴 메시지:** `copy`와 `searchSelected`에만 선택 문자열을 보낸다.
   두 명령은 기존처럼 메뉴를 열 때의 선택을 사용한다. 나머지 명령은 호스트의
   기존 선택 필드 생략 처리를 사용한다. 메뉴를 열 때 문자열을 읽는 작업 자체는
   이번 범위에 포함하지 않았다.

시리얼 RX/TX, 파싱, 파일 저장, 이벤트 판정 경로는 수정하지 않았다.

## 검증

- 다른 작업의 미커밋 변경을 제외한 별도 체크아웃에서 Release 솔루션 빌드 통과:
  경고 0, 오류 0.
- 상태 알림 회귀 검사 6개 추가. 동일 값의 새 드라이버 레코드, 모뎀 입력·출력 모드,
  자동화 예약·작업 중 상태, 연결 해제·핸드셰이크, 이전 세션 오류 제거,
  강제 갱신의 편집 복원 알림을 확인한다.
- `scripts/test_xterm_context_menu.cjs` 통과. 한글 복사·검색의 선택 캡처 유지,
  선택 없는 명령 비활성화, 자동 스크롤 토글, 비선택 명령 6종을 확인한다.
  300만 자 선택 fixture에서도 비선택 명령의 메시지는 75~87자였다.
- `scripts/test_xterm_hex_interactions.cjs` 통과. 10만 줄의 320만 바이트 집계,
  폭 변경 후 동일 바이트 수·논리 행 수·시간 차이, 64KiB 패킷 집계를 보존했다.
- 실제 WinUI/WebView2의 별도 테스트 프로세스에서 대기 중 200회 요청이 1회로
  합쳐지고 이후 요청도 1회 실행되는 것을 확인했다. 최소화·종료 상태의 생략,
  실제 창 크기 변경 후 최종 148열/22행과 화면 내용 유지를 확인했다.
  장치 연결은 하지 않았고 사용자 프로필의 SHA-256은 실행 전후 동일했다.
  상태는 테스트 훅으로 주입했으며 프로필 저장을 피하도록 테스트 프로세스를 종료했다.
- C# 회귀 검사: Core 723개, WinUI 2,036개 통과, 실패 0개.
  장치·가상 COM 환경이 필요한 WinUI 검사 17개는 건너뛰었다.

빌드·C# 검사 명령은 [개발 지침](development-workflow.md)을 따른다.
브라우저 검사는 Playwright가 있는 `NODE_PATH`에서 위 두 스크립트를 `node`로 실행한다.
실물 UART 및 장시간 안정성 시험은 이번 UI 변경 검증에서 실행하지 않았다.
