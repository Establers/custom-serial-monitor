# Virtual Modbus Device

Protocol 상단에서 **Virtual Modbus Device**를 선택한다. 이 기능은 제품이 Modbus RTU Client이고, 앱이 센서/Server 역할일 때 사용한다.

1. **GPT 작성 지침 복사**를 누르고 센서 프로토콜 PDF와 함께 GPT에 전달한다. [작성 지침](virtual_modbus_device_gpt.md), [JSON Schema](virtual_modbus_device.schema.json), [예제](virtual_modbus_device.example.json)를 함께 참고한다.
2. **JSON 추가**에서 여러 파일을 선택하거나 **JSON 붙여넣기**로 추가한다. 다시 추가하면 기존 장치를 유지하며 새 ID가 추가된다. 중복 ID, 겹친 주소, 잘못된 자료형은 전체 추가를 거절하고 이유를 표시한다.
3. 제품과 PC를 RS-485 등 알맞은 어댑터로 연결하고 시리얼 설정을 맞춘다. 같은 버스에 동일 ID의 실제 센서를 함께 연결하면 응답이 충돌하므로 가상 장치가 대체할 센서는 분리한다.
4. **시작**을 누른다. 제품 TX가 앱 RX로 들어오고, 맵에 해당하는 응답이 앱 TX로 나간다. Protocol 분석에서도 RX=Request, TX=Response 역할을 표시한다.
5. 장치와 레지스터를 선택하고 값을 입력해 **값 적용**을 누른다. 실행 중에도 ID 및 값 변경/새 JSON 추가가 가능하다. 제품의 쓰기도 메모리에 반영된다. 값 편집은 배율을 적용한 공학 단위이며 소수점은 `.`을 쓴다.
6. **JSON 저장**으로 모든 장치의 현재 ID/값을 보존한다. 정확한 비트 패턴을 보존하기 위해 저장 파일은 `rawWords`를 사용한다. 앱을 다시 열 때 저장한 JSON을 추가하고 명시적으로 시작한다. 연결 해제 후 재연결해도 자동 응답은 다시 시작하지 않는다.

현재 구성은 메모리에 있다. 저장하지 않은 수정은 종료 시 사라진다. 예제 버튼은 ID 1, 2의 예제 장치를 추가하며 동일 ID가 이미 있으면 거절한다. 레지스터 화면은 128항목씩 표시한다.

## 지원 범위

- FC01/02/03/04 읽기, FC05/06/15/16 쓰기. 지원하지 않는 정상 요청은 예외 01, 미정의/쓰기 금지 주소는 02, 잘못된 수량/값/길이는 03으로 응답한다.
- 입력/코일 비트, 16/32비트 정수, float32/64, 배율/오프셋 및 바이트/워드 순서.
- unitId 1–247. 주소 0의 방송 쓰기는 각 장치에서 검증 후 적용하지만 응답하지 않는다. 잘못된 CRC, 입력으로 들어온 예외 응답, 다른 ID에는 응답하지 않는다.
- 쓰기는 요청 전체 검증 후 적용한다. 다중 워드 값에 대한 부분 쓰기도 원시 레지스터에 그대로 반영된다. NaN 등 제품이 쓴 특수 부동소수 비트 패턴도 rawWords로 저장할 수 있다.
- 동일 장치/영역 안의 주소 겹침은 거절한다. 최대 32장치, 총 8192항목, 파일당/한 번의 추가/전체 저장 구성 최대 16 MiB, 한 번에 최대 32파일. 전체 구성은 향후 ID/워드 값이 최대 자릿수가 되어도 저장할 수 있게 미리 검증한다. 저장 파일은 재입력 검증을 거친다.

일반 TX, 시퀀스, 브리지, 직접 입력, AI/CLI의 송신 작업과 가상 장치 실행은 동시에 사용하지 않는다. 시작 시 충돌 작업을 검사하며, 실행 중 해당 송신 기능을 막는다. MOCK 포트의 텍스트 에코는 서버 테스트에 사용하지 않는다. 실제/가상 COM으로 연결한다.

**어댑터 TX 에코 있음**은 기본 꺼짐이다. 사용 중인 어댑터가 자신의 TX를 RX로 되돌리는 경우에만 중지 후 켠다. 이 모드에서는 송신 후 다음 수신 프레임이 직전 응답과 정확히 같으면 한 번 무시한다. 고정 시간 창을 두지 않아 낮은 baud/드라이버 지연도 포함한다. 다른 프레임이 먼저 오면 해당 에코 대기를 해제한다. FC05/06은 요청과 응답이 같아서 바이트만으로 실제 재요청과 에코를 자동 구별할 수 없다. 에코 없는 어댑터에서는 반드시 끈다. 에코 있는 어댑터에서 끄면 쓰기 응답이 반복될 수 있으므로 어댑터 설정을 확인한다. 상태의 에코 카운터로 확인할 수 있다.

## 처리와 안정성

RX 콜백은 제한된 큐에 바이트를 복사한다. 단일 백그라운드 작업이 요청 조립·검증·저장소 조회·응답을 수행하며, UI/파일 로깅은 기존 배치·비동기 경로를 사용한다. 큐는 128청크/256 KiB, ADU 조립 버퍼는 256바이트다. 초과 시 자동 응답을 중지하고 오류를 표시한다. 오류 이후 누락된 데이터를 이어 붙여 처리하지 않는다.

프레임 전체를 유휴 경계까지 모은 후 처리한다. CRC가 맞는 짧은 접두어만 보고 쓰기를 확정하지 않는다. 드라이버가 제공하는 검증된 유휴 경계, 관측 청크의 단조 시각 간격, 그리고 무수신 타이머를 이용한다. USB/OS 청크 시각은 UART의 바이트별 시각이 아니므로 물리적 RTU 프레임 간격 측정이나 엄밀한 규격 적합성 검사로 사용할 수 없다. 한 청크에 경계 정보 없이 합쳐진 여러 ADU를 추측해서 분해하지 않는다.

송신은 기존 직렬화된 byte-write 경로와 연결 세대 검증을 사용한다. 중지/연결 해제는 취소하고 남은 큐를 버린다. 진행 중 송신이 종료되기 전에는 다시 시작하지 않는다. 이미 드라이버에 넘긴 바이트를 되돌릴 수는 없다. 송신은 2초 취소 제한을 사용하며 드라이버가 취소에 응하지 않으면 정리가 끝날 때까지 중지 중으로 남는다.

제조사 전용 명령이나 센서의 실제 측정·교정·물리적 동작은 포함하지 않는다. 이 기능은 독자 구현한 표준 Modbus RTU 레지스터 시뮬레이터다.

공식 규격: [Application Protocol V1.1b3](https://www.modbus.org/modbus-specifications), [Serial Line V1.02](https://www.modbus.org/file/secure/modbusoverserial.pdf), [Client/Server 용어](https://www.modbus.org/news/modbus-organization-replaces-master-slave-with-client-server).
