# Modbus 값 읽기/쓰기 작업 흐름 UX 검토

후속 실제 UI 구현과 최신 빌드의 창 크기·메뉴·명령 초안 동작 확인은
[GUI 검증 기록](modbus-menu-gui-validation.md)을 따른다. 중간 단계/명령 저장 버튼 제거와
거부된 선택의 강조 복원까지 반영했다. 아래 초기 검토의 검사 수와 GUI 미실행 표기는 당시 범위다.

## 사용자 시나리오 재검토와 반영 결과

2026-11-14, 패킷 만들기·패킷 분석·단일 영역 읽기·다중 그룹·항목 정의·직접 쓰기·명령 실행과
결과 확인·정지·프로필 저장/불러오기를 코드와 회귀 검사로 점검했다. 통신 소유권과 결과 검증은
갖춰져 있었지만, 비선택 그룹 오류 발견과 설정/실행/결과의 연결에는 개선이 필요했다.
Computer Use, 실제 GUI 렌더링, 실물 UART 시험은 이번 검토에서 수행하지 않았다.

### 검증 범위

- 자동 검증 결과: Release 솔루션 빌드 경고·오류 0개, Core 전체 723개와 최종 WinUI 전체
  2,255개 통과. 실제 장치/가상 COM 환경이 필요한 WinUI 검사 17개는 제외했다.
  새 UX 회귀 시나리오 13건을 포함하며, 한/영 리소스 키 914개는 일치하고 중복이 없다.
- 포터블 Release를 재생성했다. 실행 파일·DLL·PRI·변경한 두 화면 XBF가 빌드/폴더/ZIP에서
  일치하고, 배포 파일 검사와 ZIP SHA-256 검증이 통과했다.
- 회귀 검사: 비선택 다섯 번째 그룹 오류, 정상/비활성 개수, 그룹 상태 통지와 대상 변경,
  한 번 읽기 이후의 정상 응답 표시, 빈/잘못된 프로필의 송신 없음.
- 회귀 검사: ACK/검증/불일치/실패/취소 결과를 다른 명령 선택 후에도 실제 대상으로 보존,
  폴링 재개·후속 읽기와 최근 결과의 분리, 명령 정의를 새로 불러올 때 결과 초기화.
- 회귀 검사: 고급 해석값을 접어도 전송 값 불변, 새 단계 기본 입력 복귀,
  잘못된 외부 자료형은 펼쳐 수정하되 유효한 쓰기로 자동 보정하지 않음.
- 회귀 검사: 그룹/명령 목록을 다시 구성할 때 바인딩된 목록의 선택 초기화가 저장된 선택 ID를
  지우지 않으며, 재적용 후에도 원래 선택한 대상이 유지되고 송신하지 않음.
- 기존 검사: 패킷 생성/CRC, 값 해석, 그룹/항목/명령 편집, 읽기·쓰기·상태 확인,
  자동 송신 방지, 단일 송신 소유권, 취소·응답 정리·오래된 값 표시를 함께 확인한다.
- 실제 화면의 작은 창/키보드/밝은·어두운·고대비 테마 확인은
  [수동 확인 목록](manual_test_checklist.md)의 미실행 항목으로 남긴다.

자동 실행하지 않는 현재 정책을 유지해야 한다.

## 우선순위와 근거

### P1: 명령의 최종 상태와 상단 상태가 어긋남 — 재현한 표시 버그

한 번 읽기를 하지 않은 새 ViewModel에서 비동기 명령을 실행·완료하면, `CommandStatus`는
ACK/확인 성공/조건 미충족/실패로 바뀌지만 상단 `Status`는 `Command running`으로 남을 수 있다.
이때 `IsBusy=false`, 정지 버튼은 숨겨진 상태다. 원인은 명령의 finally가 `_commandAdmitted`를
먼저 해제하고, Refresh가 그 값이 true일 때만 명령 상태를 상단 Status에 복사하는 구조다.

독립 명령의 최종 상태·대상은 다음 명시적 작업까지 함께 유지해야 한다. 폴링이 계속되는 경우에는
현재 상태와 대상이 다시 폴링을 가리키고, 마지막 명령의 자세한 결과는 별도로 보존해야 한다.
같은 실행 상태에서 다음 단계로 이동해도 ID·주소·단계 번호 변경이 상단에 통지돼야 한다.

이 문제는 검토 후 **`d10ca71`**에서 범위를 좁혀 수정했다. 새 상태·대상 회귀 검사 20개를 포함한 관련 검사
477개가 통과했고 환경이 필요한 1개는 제외했다. Release 빌드는 경고·오류 0개다.
이 수정의 실제 GUI 렌더링·실물 UART 검증은 하지 않았다. 아래 나머지 항목은 후속 제안으로 남긴다.

근거: [상태 모델](../SerialMonitor.WinUI/ViewModels/ModbusRtuViewModel.cs),
[명령 상태 모델](../SerialMonitor.WinUI/ViewModels/ModbusRtuViewModel.Commands.cs),
[회귀 검사](../SerialMonitor.WinUI.Tests/ModbusCommandHeaderTests.cs).

### P1: 비선택 그룹의 오류가 한눈에 드러나지 않음

모든 그룹 요약을 줄바꿈으로 연결하지만 화면에는 최대 3줄만 표시한다. 그룹 선택 목록은 이름과 대상 위주다.
네 번째 이후 그룹만 실패하고 나머지 폴링이 계속되면, 현재 선택 그룹이 정상인 화면에서는 오류를 놓치기 쉽다.
긴 툴팁을 확인하는 방식보다 항상 보이는 `전체 5 · 정상 4 · 오류 1` 요약과 목록의 그룹별 상태가 필요하다.

근거: [그룹 요약 생성](../SerialMonitor.WinUI/ViewModels/ModbusRtuViewModel.Groups.cs),
[요약의 MaxLines=3](../SerialMonitor.WinUI/Views/ModbusRtuView.xaml).

### P2: 기본 단일 영역 화면에도 추가 행과 설정 진입점이 남음

그룹 선택을 숨겨도 감시 그룹·명령 버튼이 있는 두 번째 행은 남는다. 프로토콜 상단 실행 줄,
표 위 설정 줄, 그룹/명령 줄, 그룹 요약이 쌓여 실제 값 표의 높이가 줄어든다.
단일 영역 설정·그룹 편집·항목 정의에서 연결된 설정을 각각 다루므로 어느 창을 열어야 할지도 어렵다.
설정 저장은 실행 중 비활성화되지만, 적용과 프로필 저장의 차이가 버튼 배치만으로는 충분히 드러나지 않는다.

### P2: 명령의 실행 대상·실행·결과·정지가 분산됨

명령은 현재 감시 그룹과 별개의 고정 ID·주소를 사용할 수 있다. 미리보기는 이를 설명하지만 긴 HEX와
확인 방식 사이에 섞여 있고, 실행 결과도 팝업 내부에 있다. 정지는 바깥 공통 상단에만 있다.
명령을 실행하는 위치에 명령명·현재 단계·대상 ID·주소와 정지를 함께 제공하고, 팝업을 닫아도 최근 결과를
알 수 있게 해야 한다. ACK만 확인한 결과와 상태 조건까지 충족한 결과는 같은 성공 문구로 합치지 않는다.

### P2: 편집·저장 단계와 고급 입력이 많음

단계 추가/수정, 명령 추가/수정, 적용, 설정 저장의 네 저장 개념이 나뉘어 있다. 모두 필수 클릭은 아니다.
실제로 적용은 현재 단계·명령 초안을 함께 반영하지만, 초안이 있으면 다른 항목 선택이 막히므로
사용자는 어느 버튼을 먼저 눌러야 하는지 문구를 읽어야 한다.

명령 편집 XAML에는 텍스트 입력 14개, 선택창 5개, 체크박스 2개가 있다. 이는 조건부 상태 필드와
접힌 값 이름 입력까지 포함한 전체 수치이며 기본 화면의 동시 표시 수는 아니다.
초보자는 대상·쓸 값·확인 방법부터 다루고, 자료형·배율·교환·단위·마스크는 필요할 때 펼치는 구성이 낫다.
HEX는 확인 가능한 미리보기로 보존하되 상시 설명문과 함께 주 작업 공간을 차지하지 않게 한다.

근거: [명령 편집 화면](../SerialMonitor.WinUI/Views/ModbusCommandEditorDialog.xaml),
[초안 적용과 선택 제한](../SerialMonitor.WinUI/ViewModels/ModbusCommandEditorViewModel.cs).

### P2: 첫 사용에서 실제로 읽을 대상까지 안내하지 못함

빈 표에는 안내 문장과 ?가 있지만 바로 누를 수 있는 대상 설정 진입점은 없다.
일반 예제 주소 0·수량 10은 장치마다 유효성이 다르며 F103RB 시험 펌웨어의 쓰기 영역 4096과도 다르다.
전역 기본값을 특정 보드 주소로 바꾸기보다는, 사용자가 명시적으로 고르는 시험 예제/프로필을 제공하면 좋다.
현재 ? 안내는 참고용으로 유지하고, 빈 표에는 `대상 설정 → 한 번 읽기`의 짧은 동선을 제공한다.

## 구체적인 정리안

상위 탭을 추가하지 않고 다음 두 도구 줄과 표를 기준으로 정리한다.

```text
프로토콜·보기 | 현재 작업·최근 결과 | 한 번 읽기 | 폴링 | 정지
대상 선택    | 대상 설정 | 직접 쓰기 | 명령 | ⋯ | ?
레지스터 표
```

- 대상이 하나면 선택 목록을 생략하고 이름·ID·영역을 짧게 표시한다. 여러 영역이면 같은 자리에 선택 목록을 둔다.
- 대상 설정에서 선택 영역의 통신 대상·표시·항목 정의를 다룬다. 그룹 관리와 프로필 저장은 명확한 이름으로 같은 설정 동선에 묶는다.
- 명령은 실행 대상 요약과 실행/정지를 같은 위치에 둔다. 편집 후 실행 위치로 자연스럽게 돌아오게 해 이중 팝업 이동을 줄인다.
- 단기에는 `목록에 반영`, `모니터에 적용`, `프로필 저장`의 적용 범위를 명확히 한다. 이후 불필요한 중간 반영 버튼을 줄이되 잘못된 초안은 보존한다.
- 명령 기본 편집은 대상·값·확인 방법을 먼저 보여준다. 별도 상태 확인 선택 시에만 상태 주소·조건을 표시하고, 비트 번호의 쉬운 입력과 원시 마스크 편집을 함께 지원하는 방안을 검토한다.
- 같은 맥락의 입력·레이블·간격을 공유한다. Header가 있는 긴 편집창에 높이 24를 일괄 강제하는 방식은 피하고, 내부 ComboBox 최소 높이와 레이블 공간을 함께 확인한다.

## 적용 순서와 확인 기준

1. 명령 최종 상태/대상 표시 버그를 작은 수정과 Fake 회귀 검사로 먼저 해결한다.
2. 그룹 전체 오류 요약, 현재 실행 대상, 최근 결과와 정지 접근성을 우선 보완한다.
3. 메뉴와 저장 버튼을 정리한 뒤 고급 입력의 접힘과 첫 사용 예제를 다룬다.

- 독립 명령이 끝나면 실제 busy/정지 표시와 상단 문구가 일치한다.
- 폴링 재개 시 명령 대상이 감시 대상처럼 남지 않고, 폴링 정지 후 예전 명령 결과가 현재 작업으로 다시 나타나지 않는다.
- 비선택 그룹의 오류도 즉시 알 수 있고, 단일 대상 사용에서 불필요한 그룹 행이 없다.
- 기본 읽기는 한 곳의 대상 설정과 한 번 읽기로 시작할 수 있다.
- 명령 실행 직전에 대상 ID·주소·쓸 값·확인 방식을 확인할 수 있다.
- 작은 창·밝은/어두운/고대비 테마·키보드 동선은 후속 렌더링 검증에서 확인한다.
- 자동 송신 방지, 단일 송신 소유권, 정지 후 진행 중 응답 정리, 쓰기 자동 재시도 금지 정책은 유지한다.

## 표 공간과 메뉴 정리 반영 (2026-11-14)

`c19a698`의 메뉴 정리에 이어 레지스터 모니터 본문을 **도구 줄 하나 + 남은 높이를 채우는 표**로 정리했다.
프로토콜·실행·공통 정지 줄은 기존 위치를 유지한다. 별도 탭이나 도구 줄은 추가하지 않았다.

- 그룹 선택을 설정 버튼과 같은 줄로 옮겼다. 그룹이 없으면 선택창을 숨긴다.
- 통신 요약 하나에 오류, 실행 불가 사유, 그룹 집계, 통계 순으로 표시한다. 잘린 원문과 모든 그룹의 상세 상태는 요약 팝업에서 확인·복사한다.
- 최근 명령의 대상·결과를 별도 행 대신 명령 팝업에 보존하고 버튼을 `명령·결과…`로 표시한다. 명령 선택이나 폴링 재개가 이전 실행 결과를 지우지 않는다.
- 좁은 창에서는 직접 쓰기와 안내를 같은 줄의 `⋯`로 옮긴다. 쓰기는 동일한 입력과 실행 가능 여부 검사를 사용한다. 명령과 설정, 상단 공통 정지는 메뉴 밖에 유지한다.
- 설정·직접 쓰기·명령의 긴 사용 설명은 필요할 때 펼친다. 실행 전 대상·값·확인 방식과 미리보기는 유지한다.
- 표의 고정 열 너비를 줄이고 이름·값에 남는 폭을 배분한다. 최소 표 너비는 660이며 더 좁으면 표 안에서 가로 스크롤한다. 기존 ListView의 행 선택과 가상화는 유지한다.
- 앱 공통 compact 버튼·입력·불투명 팝업 스타일과 테마 색을 그대로 사용한다. RX·파일 로그·시퀀스·연결 소유권·명령 실행기의 동작은 변경하지 않는다.

이 변경의 실제 GUI 확인은 별도 최종 검증 기록으로 구분한다. 자동 검사는 요약의 오류 우선순위,
연결 제한 표시, 비선택 그룹 오류 표시, 최근 명령 결과 보존과 기존 Modbus·시퀀스·프로필 회귀를 대상으로 한다.
이 소스의 Release 솔루션 빌드는 경고·오류 0, 생성된 DLL을 직접 지정한 전체 검사는 Core 723개와
WinUI 2,256개 통과·환경 조건부 17개 제외다. 이 작업에서는 GUI·COM 연결이나 장치 송신을 실행하지 않았다.
