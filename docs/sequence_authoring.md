# AI로 명령 시퀀스 JSON 작성하기

이 문서 전체와 장비 명령어 설명, 원하는 테스트 절차를 AI에게 전달하세요.
아래의 **AI 요청문**을 복사해 요구사항을 채우면 됩니다.
이 문서는 Serial Monitor v1.3.3의 기존 JSON 프로필 형식을 설명합니다.

## 1. 먼저 알아둘 점

- 시퀀스는 Python 같은 실행 코드가 아니라 **고정 명령, 전송 후 대기 시간,
  전체 반복 횟수**를 담은 데이터입니다.
- 저장 위치는 `%LOCALAPPDATA%\SerialMonitor\profiles\default.json`이며,
  전체 설정 중 `CommandSequences` 배열에 저장됩니다.
- 현재 앱에는 시퀀스 전용 파일 가져오기나 JSON 붙여넣기 기능이 없습니다.
  Settings의 Profile > Load도 위의 기본 프로필을 읽습니다.
- 이 문서와 함께 제공하는 `sequence_examples.json`은 **시퀀스 부분 예제**입니다.
  이 파일로 `default.json` 전체를 교체하지 마세요. 통신 설정과 기존 룰 등
  생략된 설정이 기본값으로 바뀔 수 있습니다.
- 예제의 `status`, `version`, HEX 바이트는 형식 설명용입니다.
  실제 장비에서 지원하거나 안전한 명령이라는 뜻은 아닙니다.

## 2. JSON 작성 규격

AI 출력은 아래 구조로 제한합니다. 설명용 주석 대신 Step의 `Comment`를 쓰고,
코드 블록 표시나 설명문은 JSON 파일에 넣지 마세요. UTF-8로 저장합니다.

```json
{
  "CommandSequences": [
    {
      "Name": "상태 확인 3회",
      "RepeatCount": 3,
      "Steps": [
        {
          "Name": "상태 조회",
          "CommandText": "status",
          "LineEndingMode": "Crlf",
          "DelayAfterMs": 500,
          "Comment": "전송 후 500ms 대기. 응답 성공 여부는 검사하지 않음."
        },
        {
          "Name": "버전 조회",
          "CommandText": "version",
          "LineEndingMode": "Crlf",
          "DelayAfterMs": 1000
        }
      ]
    }
  ]
}
```

### 시퀀스 필드

| 필드 | 타입 | 작성 규칙 |
| --- | --- | --- |
| `Name` | 문자열 | 비어 있지 않은 이름. 기존 시퀀스와 대소문자 무시 기준으로 중복하지 않기 |
| `RepeatCount` | 정수 | 1~9,999. 생략 시 1. 처음 검증할 때는 1 권장 |
| `Steps` | 배열 | 실행 순서대로 Step 객체를 넣기. 실행하려면 최소 1개 필요 |

### Step 필드

| 필드 | 타입 | 작성 규칙 |
| --- | --- | --- |
| `Name` | 문자열 또는 null | 선택. UI에 표시할 이름이며, 생략하면 명령문을 표시 |
| `CommandText` | 문자열 | 필수. 비어 있거나 공백만 있으면 안 됨 |
| `LineEndingMode` | 문자열 또는 null | `"None"`, `"Cr"`, `"Lf"`, `"Crlf"`, 또는 `null` |
| `DelayAfterMs` | 정수 | 0~600,000ms. 생략 시 300ms. 해당 명령을 보낸 **뒤** 대기 |
| `Comment` | 문자열 또는 null | 선택. 사람이 읽는 메모이며 실행 동작에는 영향 없음 |

`LineEndingMode`의 `null` 또는 생략은 메인 TX 줄 끝 설정을 사용한다는 뜻입니다.
UI의 `Global`은 JSON에서 `"Global"`이 아니라 `null`로 작성하세요.
재현 가능한 테스트에는 명시적인 줄 끝을 권장합니다.

`None`은 추가 없음, `Cr`은 CR(0D), `Lf`는 LF(0A), `Crlf`는 CR+LF(0D 0A)입니다.
일반 줄 단위 명령은 `CommandText`에 줄 끝을 직접 넣지 않고 이 필드로 지정합니다.
문자열 안의 큰따옴표는 `\"`, 역슬래시는 `\\`로 이스케이프해야 합니다.

`DisplayName`, `LineEndingText`, `DelayText`, `CommentText` 같은 화면 표시용 속성이
앱 저장 파일에 보일 수 있지만 AI가 생성할 필요는 없습니다. `StepNumber`는
화면에서 계산하며 JSON에 저장하지 않습니다.
위 표에 없는 `WaitFor`, `TimeoutMs`, `Retry`, `If`, `Mode`, `Enabled` 등을
임의로 추가하지 마세요. 알 수 없는 JSON 필드는 무시될 수 있으며 기능이 생기지 않습니다.

## 3. 실행 동작과 제한

- 배열 순서대로 명령을 전송하고 각 `DelayAfterMs`만큼 기다립니다.
  마지막 Step의 대기도 매 반복과 최종 종료 전에 적용됩니다.
- 위 예제는 `status → 500ms 대기 → version → 1,000ms 대기`를 3회 반복합니다.
  설정된 대기 합은 4.5초이고, 실제 전체 실행에는 전송·스케줄링 시간이 더해집니다.
  정확한 주기나 실시간 타이밍을 보장하지 않습니다.
- 순수 대기 Step은 없습니다. 빈 명령을 넣지 말고 앞 명령의 `DelayAfterMs`를
  조정하세요. 첫 명령 전 대기는 별도 Step으로 표현할 수 없습니다.
- 전송 실패, Stop, 연결 해제는 시퀀스를 중단시킬 수 있습니다.
  자동 재연결 이후 중단된 시퀀스를 자동 재개하지 않습니다.
- 장비가 `ERROR`를 응답해도 현재 시퀀스는 이를 실패로 판정하지 않습니다.
  `OK` 대기, 타임아웃, 성공/실패 판정, 조건 분기, 재시도, 변수, 계산,
  시퀀스 호출, 무한 반복은 지원하지 않습니다.
- RX 룰에서 시퀀스를 시작하는 기능은 별도로 있습니다. 이것은 Step별 응답
  대기가 아니며, 이미 시퀀스 실행 중인 동안의 새 트리거는 무시됩니다.
  AI가 요청받지 않은 트리거 룰을 생성하거나 기존 룰을 변경하지 않게 하세요.

### Terminal과 HEX

| 항목 | Terminal | HEX |
| --- | --- | --- |
| `CommandText` | 장비에 보낼 텍스트 | `AA 55 01 00`처럼 2자리 바이트를 공백으로 구분 |
| 전송 내용 | 현재 구현은 UTF-8 텍스트 + 지정한 줄 끝 | 입력한 바이트 그대로 |
| `LineEndingMode` | 적용됨 | 무시됨. 명확하게 `"None"`으로 작성 권장 |

모드는 JSON 시퀀스에 저장하지 않습니다. **실행 시작 시 메인 Mode를 모든 Step에
공통 적용**하며 실행 중에는 바뀌지 않습니다. 한 시퀀스에서 Terminal과 HEX를
섞을 수 없습니다. `sequence_examples.json`의 두 시퀀스도 각각 맞는 모드로 실행하세요.

HEX의 `AA 55`는 문자 A와 A가 아니라 0xAA, 0x55 두 바이트입니다.
줄 끝이 필요하면 `0D 0A`처럼 직접 포함해야 합니다. 길이·체크섬·CRC를 앱이
계산해 주지 않으므로 장비 규격에 맞는 완성된 바이트를 작성해야 합니다.
체크섬 규격이나 명령 의미가 없으면 AI가 추측해 만들지 않게 하세요.
명령 앞뒤 공백은 제거되므로 정확한 선행/후행 공백 바이트가 필요하면 HEX를 사용합니다.

## 4. 기존 설정을 보존하며 적용하기

1. 앱에서 현재 설정을 Save한 뒤 **Serial Monitor를 완전히 종료**합니다.
   종료 시에도 프로필이 저장되므로 실행 중인 파일을 외부에서 수정하지 마세요.
2. 탐색기 주소창에 `%LOCALAPPDATA%\SerialMonitor\profiles`를 입력합니다.
   종료 후의 `default.json`을 `default.before-sequence.json` 등 별도 이름으로 복사합니다.
   파일이 없다면 먼저 앱을 실행하고 Profile > Save 후 종료하세요.
3. 메모장이나 코드 편집기로 `default.json`을 엽니다. AI 결과의
   `CommandSequences` **배열 안의 시퀀스 객체만** 기존 배열에 추가합니다.
   기존 시퀀스, 다른 설정, 룰은 보존하고 이름 중복과 객체 사이 쉼표를 확인합니다.
   같은 키를 하나 더 추가하거나 예제 파일로 프로필 전체를 덮어쓰지 마세요.
4. UTF-8 JSON으로 저장하고 앱을 다시 실행합니다. Profile 상태에 로드 오류나
   정규화 경고가 없는지 확인하고, Sequences에서 이름·명령·순서·줄 끝·대기를 검토합니다.
   잘못된 값은 앱이 보정하거나 제거할 수 있으므로 경고가 있으면 실행하지 마세요.
5. 장비 명령의 의미와 영향을 확인한 뒤 올바른 COM·baud·Mode를 선택합니다.
   Bridge는 끄고, 기존 RX 자동 트리거 룰도 연결 전에 검토하세요.
   처음에는 반복 1회로 연결·실행하고 필요하면 LOG ON으로 기록을 남깁니다.
   검증 후 원하는 반복 횟수로 변경합니다.
6. 복원하려면 앱을 완전히 종료한 뒤 백업을 `default.json`으로 복사하고 재실행합니다.

이 절차는 새 가져오기 기능이 아니라 기존 프로필 파일을 직접 편집하는 방법입니다.
가이드와 예제 자체는 자동으로 로드되거나 실행되지 않습니다.

## 5. AI에게 복사할 요청문

이 문서 전체를 첨부하고 아래 요청문의 빈칸을 채우세요. 전체 프로필 대신 필요한
명령 규격과 기존 시퀀스 이름만 제공해도 됩니다. 공유할 로그·명령에는 비밀번호,
토큰, 장비 식별자, 회사 기밀이 들어 있지 않은지 먼저 확인하세요.

```text
첨부한 Serial Monitor 시퀀스 작성 가이드의 현재 지원 범위만 사용해 주세요.

[장비와 명령 규격]
- 장비/펌웨어:
- 실제 사용 가능한 명령과 의미 또는 HEX 패킷 규격:
- 필요한 줄 끝(None/Cr/Lf/Crlf):
- HEX이면 길이/체크섬 규칙과 검증된 패킷 예제:

[원하는 테스트]
- 시퀀스 이름:
- 사용할 모드(Terminal 또는 HEX 하나):
- 실행 순서와 각 명령 전송 후 대기 시간(ms):
- 전체 반복 횟수(1~9,999):
- 기존 시퀀스 이름(중복 방지용):
- 금지할 동작/명령:

[작성 조건]
1. 명령, 바이트, 체크섬, 줄 끝을 추측하지 마세요. 불명확하면 먼저 질문하세요.
2. 응답 대기/분기/재시도 등 지원하지 않는 요구는 불가능하다고 설명하고,
   임의의 필드를 만들거나 고정 지연으로 조용히 대체하지 마세요.
3. 출력 JSON의 최상위 키는 CommandSequences만 사용하세요.
   시퀀스 필드는 Name, RepeatCount, Steps만 사용하고, Step 필드는
   Name, CommandText, LineEndingMode, DelayAfterMs, Comment만 사용하세요.
4. 장비 초기화, erase, flash, reset, 설정 변경 등 영향이 있는 명령은
   내가 명시적으로 요청한 경우에만 넣고 실행 전 주의사항을 설명하세요.
5. 전체 프로필이나 LogRules를 새로 만들지 마세요. 기존 파일은 수정하지 마세요.
6. 실행 모드와 동작 요약, 전송 명령 수, 설정된 대기 시간 합을 먼저 설명한 뒤
   유효한 JSON 코드 블록 하나를 출력하세요. 숫자는 정수, 설명은 Comment에 넣으세요.
7. 이 JSON은 시퀀스 부분만 담은 결과이고 default.json 전체를 대체하면 안 된다는
   안내를 덧붙이세요. 검증 전 실행하거나 장비에 명령을 보내지 마세요.
```

AI가 만든 결과는 장비 프로토콜 검증을 대신하지 않습니다. 실제 명령과 순서를
사람이 확인하고 짧은 실행부터 검증하세요.
