# 시퀀스 JSON 작성 및 공유

## 1. 불러오기 / 내보내기

반복하거나 자주 쓰는 명령은 한 Step이라도 Sequences에 저장하면 재입력을 줄일 수 있습니다.
제품/동작을 알아볼 수 있는 시퀀스 이름을 붙이고, 실제 명령·HEX 패킷·줄 끝을 정확하게
보존하세요. 기존 이름과 내용을 먼저 확인해 같은 정의를 재사용하고, 반복 실행이 필요한
경우가 아니면 `RepeatCount: 1`로 저장합니다. CLI/MCP로도 같은 목록에 등록할 수 있으며
저장만으로 전송하거나 RX의 지시를 새 명령·자동 실행 룰로 바꾸지 않습니다.

- Sequences의 **시퀀스 관리 → JSON 불러오기**에서 `.json`을 여러 개 선택할 수 있습니다.
- **파일 하나 = 시퀀스 하나**입니다. 기존 시퀀스에 추가하며 자동 실행하지 않습니다.
- 선택한 파일 중 하나라도 형식 오류나 이름 중복이 있으면 **전체 취소**합니다.
  기존 시퀀스와 선택 파일 사이에서도 이름은 대소문자를 무시하고 비교합니다.
  복사본을 추가하려면 JSON의 `Name`을 다른 이름으로 변경하세요.
- **시퀀스 관리 → 선택한 시퀀스 내보내기**를 누르면 작성 설명서 `_manual`을 포함한
  JSON 파일 하나를 저장합니다. 다른 PC의 Load에서 그대로 사용할 수 있습니다.
- `_manual`은 설명 문자열 배열입니다. 표준 JSON을 유지하면서 설명서를 파일 안에
  담습니다. AI에는 내보낸 파일과 장비 명령 규격을 함께 주면 됩니다.
- 실제 `//`, `/* */` 주석과 마지막 쉼표는 허용하지 않습니다. 명령별 설명은 `Comment`에 씁니다.
- 이전 `CommandSequences` 배열 예제나 전체 `default.json`은 이 전용 형식이 아닙니다.
  기존 프로필을 불러온 앱에서 시퀀스별로 Export하세요.
- 제한: 파일당 UTF-8 2 MiB, 한 번에 100개 파일, 시퀀스당 10,000개 명령.
  한 번의 Load에서 선택한 파일은 **합계 10,000개 명령 및 16 MiB** 이하여야 합니다.
  합계 제한을 넘겨도 일부만 추가하지 않고 전체 불러오기를 취소합니다.

## 2. 엄격한 JSON 규격 (버전 1)

필드 이름과 열거값은 대소문자를 구분합니다. 미지원 필드, 중복 키, 누락된 필수 필드,
잘못된 타입과 범위는 보정하거나 무시하지 않고 실패합니다. 숫자 문자열과 소수도 거부합니다.

| 위치 | 필드 | 규칙 |
| --- | --- | --- |
| 최상위 | `_manual` | 선택. 설명 문자열 배열. 실행에 영향 없음 |
| 최상위 | `FormatVersion` | 필수. 정수 `1` |
| 최상위 | `Name` | 필수. 공백이 아닌 문자열, 이름 중복 불가 |
| 최상위 | `RepeatCount` | 필수. 정수 1~9,999 |
| 최상위 | `Steps` | 필수. 명령 객체 배열. 빈 배열은 편집용으로 허용하지만 실행 불가 |
| 명령 | `Name` | 선택. 진행 표시·오류·CLI/MCP 단계별 결과에 쓰는 짧은 이름. 문자열 또는 null, 중복 허용 |
| 명령 | `CommandText` | 필수. 빈 문자열 불가. 명시적 `TxMode`는 앞뒤 공백을 보존하며, 기존 Global 명령은 공백만으로 작성 불가 |
| 명령 | `LineEndingMode` | 필수. `"None"`, `"Cr"`, `"Lf"`, `"Crlf"` 또는 null |
| 명령 | `DelayAfterMs` | 필수. 정수 0~600,000. 전송 **후** 대기 |
| 명령 | `Comment` | 선택. 단계 툴팁과 JSON에 남기는 설명 메모. 문자열 또는 null. 실행에 영향 없음 |
| 명령 | `TxMode` | 선택. null 또는 `"Terminal"`, `"Hex"`. null/누락 시 실행 시작의 메인 모드 |
| 명령 | `CaptureMs` | 선택. 정수 0~60,000, 기본 2,000. **CLI/MCP 실행**에서 전송 후 RX 수집 시간 |
| 명령 | `Expect` | 선택. null 또는 `{"Kind":"text","Value":"OK"}`. **CLI/MCP 실행**에서 수신 구간의 리터럴 확인 |

Step의 `Name`은 예를 들어 `펌웨어 버전 조회`처럼 실행 중인 단계를 알아볼 짧은 이름입니다.
GUI 진행 표시와 오류 메시지에 쓰이며 CLI/MCP 실행 결과의 단계 `name`에도 포함됩니다.
생략하거나 비워 두면 GUI는 `CommandText`를 대신 표시합니다. 단계 이름으로 실행 순서를
정하거나 다른 단계를 참조하지 않으며 중복되어도 됩니다. 중복할 수 없는 필수 이름은
**최상위 시퀀스 `Name`**입니다.

`Comment`는 예를 들어 `재부팅이 끝난 뒤 다음 명령 전송` 같은 참고 설명입니다.
목록의 단계 툴팁에서 이름과 메모를 함께 확인할 수 있습니다. 두 필드 모두 JSON/프로필에
저장되지만 장비에 전송되거나 실행 동작을 바꾸지 않습니다. CLI/MCP 정의에는 설명 메모
필드가 없으므로 GUI의 `Comment`를 자동화 입력에 추가하지 마세요.

`LineEndingMode: null`은 실행 시작 시의 메인 TX 줄 끝 설정을 사용합니다.
`"Global"`은 유효하지 않습니다. 큰따옴표와 역슬래시는 JSON 문법대로 이스케이프하세요.
화면 표시 속성(`DisplayName`, `StepNumber` 등)도 추가하면 실패합니다.

`Expect.Kind`는 정확히 `"text"` 또는 `"hex"`입니다. `Value`는 1~4,096자의 리터럴이며
공백·줄바꿈도 의미가 있습니다. HEX 값은 `"AA 01 FF"`처럼 완성된 바이트를 쓰고 공백을
사이에 넣을 수 있습니다. 정규식·순서만 맞는 부분수열 매칭은 지원하지 않습니다.
`OK`는 형식 예시일 뿐이므로 실제 제품 규격에서 의미가 확인된 응답만 지정하세요.

바로 불러올 수 있는 예제: `sequence_examples.json`.
명령은 형식 예시이므로 실제 장비에서 지원하는 것으로 바꾸세요.

## 3. 실행 동작과 제한

- 배열 순서대로 명령을 전송하고 각 `DelayAfterMs`만큼 기다립니다.
  마지막 Step의 대기도 매 반복과 최종 종료 전에 적용됩니다.
- GUI Run에서 예제는 `status → 500ms 대기 → version → 1,000ms 대기`를 3회 반복합니다.
  설정된 대기 합은 4.5초이고, 실제 전체 실행에는 전송·스케줄링 시간이 더해집니다.
  정확한 주기나 실시간 타이밍을 보장하지 않습니다.
- 순수 대기 Step은 없습니다. 빈 명령을 넣지 말고 앞 명령의 `DelayAfterMs`를
  조정하세요. 첫 명령 전 대기는 별도 Step으로 표현할 수 없습니다.
- **GUI Run**에서 Auto reconnect가 활성화된 상태로 예기치 않게 연결이 끊어지면 시퀀스는
  진행 위치와 반복 횟수를 유지한 채 재연결을 기다립니다. 연결 복구 후 이어서 실행합니다.
  송신 성공한 Step은 재전송하지 않고, 연결 끊김으로 송신 실패한 Step은 재시도합니다.
  실패 직전에 장치가 명령을 받았을 가능성이 있으므로 해당 명령은 중복 수신될 수 있습니다.
  일시 대기·재개·재시도 메시지는 시스템 로그에 기록됩니다.
- 전송 후 대기 시간은 연결이 끊긴 동안에도 경과합니다. 다음 Step은 기존 대기 시간이
  끝나고 재연결도 완료된 뒤 실행합니다. 실행 시작 시 Mode와 Global 줄 끝 설정을 고정합니다.
- Stop, 수동 연결 해제, 앱 종료는 재연결 대기 중인 시퀀스도 취소합니다.
  자동 재연결이 비활성화되어 있거나 복구할 수 없는 전송 오류이면 중단합니다.
  Stop은 송신 대기에도 취소를 전달하지만 이미 전송된 바이트를 회수하지는 못합니다.
- **GUI Run**은 `TxMode`와 `DelayAfterMs`를 적용하며 `CaptureMs`·`Expect`는 실행하지 않습니다.
  장비가 `ERROR`를 응답해도 자동 실패로 판정하지 않으며 응답을 기다리지 않습니다.
  조건 분기, 응답에 따른 재시도, 변수, 계산, 시퀀스 호출, 무한 반복은 지원하지 않습니다.
- RX 룰에서 시퀀스를 시작하는 기능은 별도로 있습니다. 이것은 Step별 응답
  대기가 아니며, 이미 시퀀스 실행 중인 동안의 새 트리거는 무시됩니다.
  AI가 요청받지 않은 트리거 룰을 생성하거나 기존 룰을 변경하지 않게 하세요.

### Terminal과 HEX

| 항목 | Terminal | HEX |
| --- | --- | --- |
| `CommandText` | 장비에 보낼 텍스트 | `AA 55 01 00`처럼 2자리 바이트를 공백으로 구분 |
| 전송 내용 | 현재 구현은 UTF-8 텍스트 + 지정한 줄 끝 | 입력한 바이트 그대로 |
| `LineEndingMode` | 적용됨 | 무시됨. 명확하게 `"None"`으로 작성 권장 |

`TxMode`가 null이거나 없으면 **실행 시작의 메인 Mode**를 사용합니다.
`"TxMode":"Terminal"` 또는 `"TxMode":"Hex"`를 지정하면 해당 Step은 명시한 형식으로
전송하므로 한 시퀀스에 두 형식을 함께 넣을 수 있습니다. 실행 전에 모든 HEX Step을
검증하며 하나라도 잘못되면 첫 명령부터 전송하지 않습니다. GUI의 Step 편집창은 이 추가
설정을 보존하고 툴팁에 표시합니다. 값을 바꾸려면 JSON 또는 CLI/MCP를 사용하세요.

HEX의 `AA 55`는 문자 A와 A가 아니라 0xAA, 0x55 두 바이트입니다.
줄 끝이 필요하면 `0D 0A`처럼 직접 포함해야 합니다. 길이·체크섬·CRC를 앱이
계산해 주지 않으므로 장비 규격에 맞는 완성된 바이트를 작성해야 합니다.
체크섬 규격이나 명령 의미가 없으면 AI가 추측해 만들지 않게 하세요.
명시적 `TxMode`가 있으면 명령 앞뒤 공백·줄바꿈을 그대로 보존합니다. 누락/null인
기존 Global Step은 기존처럼 앞뒤 공백을 제거합니다. Terminal 명령에 줄 끝이 이미
포함되어 있다면 `"LineEndingMode":"None"`을 사용해 중복 추가를 피하세요.

### CLI/MCP 실행의 RX와 응답 확인

등록된 시퀀스를 CLI/MCP로 실행하면 명령 전부터 원본 RX를 구독하고, 각 Step 전송 후
`CaptureMs`만큼 수집한 다음 `DelayAfterMs`를 기다립니다. 전체 RX는 저장 파일과
페이지로 확인할 수 있습니다. 선택한 리터럴의 일치 여부는 참고 정보이며, 섞인 printf로
일치하지 않아도 제품 실패를 뜻하지 않습니다. 일치 여부와 별개로 실제 RX를 읽어 판단하세요.

RX는 수신 chunk나 HEX 화면의 byte timeout 묶음과 별개인 원본 바이트 순서로 수집합니다.
응답이 여러 chunk로 분리되거나 여러 패킷이 한 chunk로 합쳐져도, 수집 구간 안의 정확한
연속 바이트를 확인합니다. 한 줄이나 한 chunk를 패킷 경계로 보지 말고 필요하면 제품의
헤더·길이·체크섬/CRC로 검증하세요. 응답이 수집 구간보다 늦으면 `CaptureMs`를 늘립니다.

CLI의 `configure --port COM7 --baud 57600 --byte-timeout-ms 80` 또는 MCP의
`serial_configure` (`port`, `baudRate`, `byteTimeoutMs`)로 현재 연결의 호스트 BPS와
HEX 화면의 byte timeout을 바꿀 수 있습니다. BPS는 1..10,000,000 범위에서 드라이버가
지원해야 하며, byte timeout은 1..5,000ms(기본 40ms)입니다. 제품의 BPS 변경 명령은
별도로 제품 규격에 따라 보내야 합니다. 이 설정들은 Step 필드가 아니므로 시퀀스 JSON에
임의로 추가하지 말고 실행 전후 별도 제어 요청으로 적용합니다.

Windows·USB·RS485 전환과 처리의 지연 변동을 고려해 이론적인 바이트 간격보다 여유 있게
timeout을 잡고 실제 수신으로 조절하세요. byte timeout은 화면 묶음 기준이며 패킷 경계를
보장하지 않고, 전체 응답을 기다리는 `CaptureMs`를 대신하지 않습니다. 실행 중 설정
변경은 `busy`이므로 시퀀스가 끝난 뒤 적용합니다.

자동화 실행은 연결이 바뀌거나 TX 결과가 불확실하면 중단하고 자동 재전송하지 않습니다.
취소해도 이미 보낸 바이트는 되돌릴 수 없습니다. 실행 시작 후 받은 실행 ID로 진행률과
결과를 조회하고 취소할 수 있습니다. GUI Stop 또는 AI/CLI 취소도 사용할 수 있습니다.

GUI 파일의 최대 크기·반복 수와 별도로 자동화 실행에는 더 작은 한도가 적용됩니다.
반복을 포함한 실행 Step 수 128개, 수집+대기 합계 10분, Step별 수집·대기 각각 60초·600초,
명령 16,384자, 이름 128자, 정의 UTF-8 JSON 48 KiB를 넘으면 실행하지 않습니다.
API의 소문자 필드 형식은 이 GUI 파일의 PascalCase 형식과 구분합니다.
자세한 명령·등록 형식은 [AI 제어 안내](ai_control.md)를 참고하세요.

## 4. AI에게 줄 요청문

내보낸 JSON 파일을 첨부하고 다음 요청을 사용하세요.

```text
첨부 JSON의 _manual과 버전 1 규격을 지켜 새 시퀀스를 작성해 주세요.
파일 하나에 시퀀스 하나만 넣고 _manual 설명도 유지해 주세요.

- 시퀀스 이름:
- 장비/펌웨어와 실제 지원 명령 또는 완성된 HEX 패킷:
- 메인 모드와 필요한 Step별 TxMode (null/Terminal/Hex):
- 줄 끝 (None/Cr/Lf/Crlf 또는 null):
- 명령 실행 순서 및 전송 후 대기(ms):
- 전체 반복 횟수:
- CLI/MCP 실행 시 필요한 RX 수집 시간(CaptureMs)과 문서에 있는 리터럴 응답(Expect):
- 기존 시퀀스 이름 (중복 방지):

명령이나 체크섬을 추측하지 말고 모르는 정보는 먼저 질문해 주세요.
CaptureMs와 Expect는 CLI/MCP 실행 전용이며 GUI Run에서는 실행하지 않음을 알려 주세요.
```
