# Modbus 숫자 입력 폭 정리

짧은 ID·주소·수량에도 가로 공간을 절반씩 배분하던 편집창을 줄였다.
이름·여러 값·값 이름 목록·HEX 미리보기는 남는 폭을 사용한다.

| 화면 | 창 최대 폭 변경 |
| --- | --- |
| 명령 편집 | 640 → 480 |
| 감시 그룹 편집 | 600 → 460 |
| 항목 정의 | 600 → 460 |
| 패킷 만들기 | 520 → 440 |

- ID는 104, 일반 숫자는 최대 128, 배율·확인 시간은 최대 144, 명령의 쓸 값은 최대 176 폭을 사용한다.
- 숫자 둘만 있는 줄은 입력칸을 왼쪽에 모은다. 이름·설명·목록을 위한 공간까지 숫자 칸이 늘어나지 않는다.
- 좁은 패킷 편집의 주소·AND·OR 세 칸은 사용 가능한 폭에 맞춰 줄어든다.
- 레이블은 기존 줄바꿈을 유지하고 같은 줄의 입력 영역은 아래에 맞춘다.
- 입력 길이·자료형·HEX/지수 표기·유효성 검사·읽기/쓰기·프로필 동작은 바꾸지 않는다.
- 기존 세로 스크롤, 여러 값 입력의 별도 스크롤과 여백을 유지한다. 탭이나 입력 줄을 추가하지 않는다.

이번 변경은 네 편집창의 XAML에 한정한다. 레지스터 표 폭과 다른 화면의 공통 스타일은 바꾸지 않는다.
GUI 실측 확인은 빌드·자동 검사와 구분해서 기록한다.

## 검증

- Release 솔루션 빌드: 경고·오류 0.
- 해당 빌드의 Modbus·Protocol 관련 기존 검사: 499개 통과, 가상 포트 환경 조건부 1개 제외.
- 기준 커밋 `3e9d689`와 네 XAML의 바인딩·이벤트·행 구조·읽기 전용/여러 줄 동작·입력 길이 제한을 대조해 모두 유지됨을 확인했다.
- 이 변경 작업에서는 GUI 조작·COM 연결·실제 송신을 실행하지 않았다.

## 포터블 레이아웃 자동 검사

```powershell
.\scripts\test_modbus_layout_native.ps1 -AppPath .\release\SerialMonitorPortable\SerialMonitor.WinUI.exe
```

별도 자식 프로세스에서 실제 포터블의 WinUI 창과 펼침 영역을 생성해 크기를 측정한다.
Computer Use·마우스/키보드 입력·COM 연결·송신은 사용하지 않는다. 테스트가 끝나면 자식만 종료하고
프로필 해시가 유지됐는지 검사한다.

- 1280×900 및 800×600 창에서 항목·그룹·명령 편집, 오류 표시, 패킷 생성 20개 기능,
  대상 설정·직접 쓰기·명령·도움말·필터·값 해석을 검사한다.
- 긴 이름, 32개 명령 단계, 여러 줄 값 이름, 최대 길이 HEX, 80행 레지스터 표를 사용한다.
- 입력 초점의 지우기 버튼을 포함한 유효 숫자의 폭, 버튼/레이블 높이, 하단 버튼 범위,
  가로·세로 스크롤 끝 도달과 마지막 항목 접근을 확인한다.
- 긴 목록 이름은 줄임표를 사용하고 전체 문자열 툴팁이 연결됐는지 확인한다.
- 결과와 스크롤 실측값은 `artifacts/modbus-layout-native/<실행 ID>/result.json`, 검사한 EXE/DLL
  해시는 같은 폴더의 `payload-hashes.json`에 남는다.

측정은 실행 PC의 현재 배율과 언어를 사용하며, 결과에 실제 배율을 기록한다.
다른 DPI·접근성 글꼴 배율이나 육안으로 보는 픽셀 모양까지 검증하는 검사는 아니다.
범위를 벗어난 긴 붙여넣기는 입력을 줄이지 않고 커서 이동으로 끝까지 볼 수 있는지 따로 확인한다.

2026-11-14 최종 포터블 검증에서는 현재 한국어·배율 1.0 환경에서 레이아웃 78건과 스크롤 끝
도달 58건이 통과했다. 긴 이름이 목록에서 잘려 전체 내용을 확인할 수 없던 부분은 줄임표와
전체 문자열 툴팁으로 수정했다. 관련 Modbus·Protocol 회귀 검사는 552건 통과, 가상 포트 환경
조건부 1건 제외이며, 검사 전후 프로필 해시도 유지됐다.
