# Modbus 폼 정렬과 숫자 입력 폭

화면마다 임의의 숫자 폭을 조합하던 방식에서 공통 기준열을 사용하는 폼으로 정리했다.
대상 설정·감시 그룹·항목·명령·패킷 편집의 라벨과 입력칸이 같은 세로선에 놓인다.

## 적용 원칙

[NN/g의 그리드·정렬 원칙](https://www.nngroup.com/articles/good-visual-design/)과
[근접성 원칙](https://www.nngroup.com/articles/gestalt-proximity/)을 참고했다.
관련 라벨과 입력은 가깝게 배치하고 여러 행이 공통 열과 간격을 사용한다.
아래 수치는 일반 이론의 의무 규격이 아니라 이 앱의 좁은 편집창과 입력 길이에 맞춘 값이다.

- 편집 폼은 첫 열 128 DIP, 열 간격 8 DIP로 두 번째 열을 왼쪽에서 136 DIP에 시작한다.
  오른쪽 열은 남은 폭 전체를 사용하고, 대상 설정의 기존 균등 2열도 각 칸을 열 끝까지 채운다.
- 라벨과 입력칸은 별도 행으로 나누고 4 DIP 간격을 둔다. 긴 라벨이 줄바꿈돼도 같은 행의
  입력칸은 공통 높이에서 시작한다. 별도 라벨의 접근성 이름도 입력칸에 연결한다.
- 숫자 입력과 기능 선택 스타일에 고정 폭·최대 폭을 두지 않는다. 짧은 왼쪽 폭은 Grid가 결정하고,
  오른쪽 수량·배율·쓸 값·응답 제한·드롭다운은 남은 열을 끝까지 채운다. 명령의 쓸 값 176 DIP
  제한도 제거했다. 독립된 FIFO 주소는 128 DIP를 유지하고 AND·OR 마스크는 두 번째 영역을 나눈다.
- 상태 확인 기능·장치 식별 접근·단일 진단은 숫자를 첫 열에, 긴 선택 이름을 두 번째 열에 둔다.
  진단 에코는 선택기를 두 열 전체에 펼친다. 키보드 순서도 화면의 좌우 순서에 맞춘다.
  폭을 넘는 선택 이름은 전체 문자열 툴팁으로 확인할 수 있다.
- 바이트/워드 교환 옵션도 같은 두 열에 맞춘다. 레지스터 표는 기존의 헤더/행 공통 열을 유지한다.
- 입력값·바인딩·이벤트·유효성 검사·읽기/쓰기·프로필 동작은 유지한다.

| 화면 | 창 최대 폭 |
| --- | --- |
| 명령 편집 | 480 DIP |
| 감시 그룹 편집 | 460 DIP |
| 항목 정의 | 460 DIP |
| 패킷 만들기 | 440 DIP |

공통 그리드/라벨 스타일은 `CompactControlStyles.xaml`에 둔다. 기존 세로 스크롤과 여러 값
입력의 별도 스크롤, 오버레이 스크롤바용 여백, 하단 버튼 배치를 유지한다.
실행 중인 포터블 경로를 다시 게시하면 파일을 삭제하기 전에 중단하도록 검사한다.

## 포터블 레이아웃 자동 검사

```powershell
.\scripts\test_modbus_layout_native.ps1 -AppPath .\release\SerialMonitorPortable\SerialMonitor.WinUI.exe
```

별도 자식 프로세스에서 실제 포터블의 WinUI 창과 펼침 영역을 생성해 크기를 측정한다.
Computer Use·마우스/키보드 입력·COM 연결·송신은 사용하지 않는다. 테스트가 끝나면 자식만 종료하고
프로필 해시가 유지됐는지 검사한다.

- 1280×900 및 800×600 창에서 항목·그룹·명령 편집, 오류 표시, 패킷 생성 20개 기능,
  대상 설정·직접 쓰기·명령·도움말·필터·값 해석을 검사한다.
- 긴 이름, 32개 명령 단계, 여러 줄 값 이름, 최대 길이 HEX, 80행 레지스터 표를 사용한다.
- 폼의 공통 좌우 기준선, 첫 열 폭, 8/4 DIP 간격, 라벨/입력의 왼쪽·위쪽 정렬과 접근성 이름을 측정한다.
- 모든 폼의 TextBox/ComboBox가 할당된 열의 오른쪽 끝까지 채우는지 검사하고 입력 폭·할당 폭·빈 폭을 기록한다.
- 화면에 내부 ViewModel 이름이 표시되거나, 제목 없는 한 줄 입력/선택칸이 24 DIP 기준(허용 오차 2 DIP)을 넘으면 실패한다.
- 입력 초점의 지우기 버튼을 포함한 유효 숫자의 폭, 버튼/레이블 높이, 하단 버튼 범위,
  가로·세로 스크롤 끝 도달과 마지막 항목 접근을 확인한다.
- 긴 목록 이름은 줄임표를 사용하고 전체 문자열 툴팁이 연결됐는지 확인한다.
- 결과와 스크롤 실측값은 `artifacts/modbus-layout-native/<실행 ID>/result.json`, 검사한 EXE/DLL
  해시는 같은 폴더의 `payload-hashes.json`에 남는다.

측정은 실행 PC의 현재 배율과 언어를 사용하며, 결과에 실제 배율을 기록한다.
다른 DPI·접근성 글꼴 배율이나 육안으로 보는 픽셀 모양까지 검증하는 검사는 아니다.
범위를 벗어난 긴 붙여넣기는 입력을 줄이지 않고 커서 이동으로 끝까지 볼 수 있는지 따로 확인한다.

## 최종 검증 (2026-11-14)

- 한국어·배율 1.0, 1280×900 및 800×600: 화면 82건, 공통 폼 그리드 140건, 스크롤 끝 도달
  58건 통과. 긴 단일 진단 이름과 장치 식별의 가장 긴 선택값도 포함한다.
- 실제 최종 포터블 결과: `artifacts/modbus-layout-native/94ebadd023314e4c8ed2262127738c5f/result.json`.
  검사 전후 프로필 해시는 유지됐고 COM 연결·송신은 없었다.
- Release 빌드 경고·오류 0. Modbus·Protocol 회귀 검사 573건 통과, 가상 포트 환경 조건부 1건 제외.
- 기준 `af12b67`과 다섯 XAML의 입력값·이벤트·데이터 바인딩·읽기 전용/여러 줄/입력 길이 제한을
  대조해 유지됨을 확인했다. 진단 선택기 열만 표시 상태에 따라 이동하는 속성을 추가했다.
- 최종 EXE·DLL·PRI 및 변경한 XBF 6개가 빌드 결과·포터블·ZIP에서 일치하고 ZIP SHA-256도 확인했다.
- 실행 중 게시 차단 검사는 예외 발생 전후 기존 포터블 파일 787개의 해시가 유지됨을 확인했다.

## 빈 헤더 템플릿 회귀 수정

독립 라벨로 전환한 뒤에도 TextBox/ComboBox 공통 스타일에 `HeaderTemplate`이 남아 있었다.
Header가 없는 컨트롤에서 템플릿의 `{Binding}`이 상위 DataContext를 받아 내부 클래스명을
표시하고 입력 높이가 60–76 DIP까지 늘어났다. 실제 Header가 있는 컨트롤에만 템플릿을
명시하고 공통 스타일에서는 제거했다. 같은 그리드의 입력값·바인딩·이벤트는 유지한다.

수정 전 실제 포터블의 그룹 편집 4개 사례에서 내부 이름 노출·높이 검사 12건이 실패하는 것을
확인했다. 수정 후 위 전체 82개 사례에서 같은 검사를 통과했다. 패킷 FC03 창은 440×477에서
440×373 DIP로 줄었다. 검사 결과는 현재 한국어·배율 1.0 환경에 해당한다.

## 오른쪽 끝선 채우기 (2026-11-15)

패킷 만들기의 기능·수량과 그룹/항목/명령 편집의 오른쪽 숫자 칸에 고정 폭이 남아 있었다.
숫자 스타일의 Width/MaxWidth, 기능 선택의 128 DIP 제한, 명령 값의 176 DIP 제한을 제거하고
각 Grid 열을 Stretch로 채운다. 왼쪽 128 DIP 열과 기존 24 DIP 높이·8/4 DIP 간격은 유지한다.
기존 대상 설정의 균등 열도 모든 입력칸이 자기 열을 끝까지 채우는지 같은 검사로 확인한다.

- 수정 전 FC04 포터블은 1280×900 및 800×600에서 오른쪽 칸이 할당된 258 DIP 중 128 DIP만
  사용해 새 오른쪽 끝선 검사 2건이 실패했다.
- 수정 후 같은 기능·수량은 모두 258 DIP를 채워 빈 폭이 0 DIP였다.
- 전체 화면 84건, 폼 그리드 140건, 입력/선택칸 302건에서 오른쪽 끝선 오차 0 DIP.
  스크롤 끝 도달 61건도 통과했다. 현재 한국어·배율 1.0 환경에서 측정했다.
- 전체 결과: `artifacts/modbus-form-right-edges/artifacts/modbus-layout-native/9420a7c84c354e22bac165937871b647/result.json`.
- 기존 포터블 경로 교체 후 FC04 두 창 크기를 재검사했다. 결과:
  `artifacts/modbus-layout-native/6d9188bdb15e4f479d3efbe46633d56e/result.json`.
- Release 빌드 경고·오류 0, Modbus·Protocol 회귀 검사 581건 통과·가상 포트 조건부 1건 제외.
- 다섯 XAML은 폭과 가로 정렬 외의 컨트롤·바인딩·이벤트·접근성 속성이 동일함을 대조했다.
  검증한 포터블 파일 787개와 ZIP을 기존 경로로 복사한 뒤 해시가 모두 일치함을 확인했다.
  프로필은 유지됐고 Computer Use·COM 연결·송신은 사용하지 않았다.
