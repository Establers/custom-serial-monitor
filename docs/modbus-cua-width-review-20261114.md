# Modbus 숫자칸·팝업 실제 화면 확인 (2026-11-14)

## 확인 환경과 범위

- 한국어, 화면 배율 100%, 실제 창 1186×793에서 Computer Use로 확인했다.
- 설치본과 포터블의 실행 파일 이름이 같아 제어 도구가 창 소유자를 혼동했다. 최신 소스
  `fbfd6a0`에 수정 `7550655`를 적용한 `UpdatePreviewBuild=true` Debug 실행 파일로
  별도 이름의 창을 열었다. 최종 Release 포터블을 직접 조작했다고 표현하지 않는다.
- 수정 후 실행 파일의 SHA-256은
  `EEA1748198E9EA31BC87433265F7168187E71F0C400AE22EB7CFA1A98C02DE7F`,
  관리 DLL은 `11674F9ADF648244844108BD658AD1626DDD516E4FBD2D1E8AA06B4F632D1F37`다.
- 자동 재연결을 끄고 존재하지 않는 포트를 지정한 임시 프로필을 사용했다. 실제 포트 연결,
  읽기/쓰기 송신, 명령 실행은 하지 않았다. 이 기록은 레이아웃과 편집 동작 확인이다.

## 발견한 문제와 수정

별도 라벨을 사용하는 입력칸에도 공통 `HeaderTemplate`이 남아 있었다. 빈 Header에서
템플릿의 Binding이 상위 DataContext를 받아 `SerialMonitor.WinUI.ViewModels...`라는
내부 클래스명을 표시하고, 입력칸 높이와 대화상자 길이를 늘렸다. 감시 그룹 창에서
실제로 확인했다.

그룹·항목·명령·패킷 편집기의 공통 TextBox/ComboBox 스타일에서 해당 템플릿을 제거하고,
실제 Header를 가진 컨트롤에만 명시했다. 입력값 바인딩·이벤트·통신 처리는 바꾸지 않았다.
실제 생성된 TextBlock에 내부 클래스명이 나오면 자동 검사도 실패하도록 보강했다.

## 직접 조작하고 본 결과

| 화면 | 실제 확인한 내용 |
| --- | --- |
| 대상 설정 팝업 | ID `247`, 주소 `65535` 및 `0xFFFF`, 수량 `1`이 보인다. 포커스 상태에서도 주소와 지우기 버튼이 겹치지 않는다. `03 · Holding registers`가 끝까지 보인다. |
| 감시 그룹 편집 | 수정 전 내부 클래스명 노출을 재현했다. 수정 후 사라졌으며 라벨·입력칸이 같은 높이에서 시작한다. 최대 주소와 긴 그룹 이름을 확인했다. |
| 항목 정의 편집 | 숫자칸·자료형·접근 권한이 정렬된다. 긴 목록 이름은 말줄임과 전체 문자열 툴팁으로 확인했다. 아래로 스크롤해 항목 추가/수정과 적용·취소 버튼에 접근했다. 취소하면 그룹 창으로 돌아간다. |
| 직접 쓰기 팝업 | 주소 `0xFFFF`, 원시 값 `65535`와 읽기 전용 항목 오류 문구가 팝업 안에 보인다. 쓰기는 실행하지 않았다. |
| 명령 팝업·편집 | 저장된 여러 단계 명령의 요약, 이름, ID·주소·쓸 값이 보인다. 자료형·배율·통신 옵션을 펼치고 아래로 스크롤해 결과 확인 안내와 하단 적용·취소 버튼을 확인했다. |
| 패킷 만들기 | FC03 기본 화면에서 기능명, ID·주소·수량, 안내, HEX 미리보기, 하단 버튼이 보인다. 숫자 입력 폭은 128 DIP 기준을 유지한다. HEX 복사나 송신은 하지 않았다. |

일반 숫자칸과 여러 값을 받는 영역의 폭을 구분한
[공통 폼 배치](modbus-numeric-field-layout.md)를 유지하며, 탭이나 상시 표시 행은 추가하지 않았다.

## 자동 검사

- 수정 전 실제 Debug preview의 `groups-long` 2개 사례에서 내부 클래스명 검사 실패를 확인했다.
  수정 후 같은 2개 사례가 통과했다. 수정 전 실행의 바이너리 해시는 별도로 보관되지 않았으므로
  다른 세션이 게시한 Release와의 바이너리 비교 근거로 사용하지 않는다.
- 수정 후 Debug preview: 1280×900·800×600의 82개 레이아웃 사례, 140개 공통 폼 그리드 통과.
  다른 패킷 기능, 긴 내용, 오류 표시, 스크롤 끝 도달은 이 자동 검사 범위다.
- 수정 소스의 Release 솔루션 빌드: 경고 0, 오류 0.
- 같은 빌드의 x64 WinUI Modbus·Protocol 관련 테스트: 554개 통과, 가상 포트 조건부 1개 제외.

## 도구 한계와 원상 복원

패킷 기능을 더 바꾸려는 단계에서 Computer Use가 `unknown screenshotId screenshot-0`,
`Computer Use helper already has an active request`를 반복했다. 대기 후 재시도와 JavaScript
세션 초기화를 거쳐도 다시 발생해 입력을 중단했다. 다른 패킷 기능 및 800×600의 추가
수동 검사는 완료하지 못했다. 자동 검사 결과와 직접 화면 확인 범위를 구분한다.

이 세션이 연 preview 프로세스만 실행 경로를 대조해 종료했다. 실행 중인 Serial Monitor
프로세스가 없는 것을 확인하고 원래 프로필을 바이트 그대로 복원했으며, 시작 시 SHA-256과
일치하는 것을 확인했다. 실제 보드 상태는 변경하지 않았다.
